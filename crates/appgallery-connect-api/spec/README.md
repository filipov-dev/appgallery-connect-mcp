# Спецификация AppGallery Connect API

У Huawei нет машинной спецификации Connect API: есть только страницы справочника.
MCP-инструменты операций генерируются при сборке из двух файлов, которые мы ведём сами:

| Файл | Что это |
| --- | --- |
| `openapi.json` | Снимок API в формате OpenAPI 3.0: операции, параметры, тела запросов, ответы. Собран по страницам справочника и правится вручную. |
| `overlay.toml` | Файл-дополнение: всё, чего нет в справочнике, — группы, наборы инструментов, имена инструментов, уровни доступа, исключённые операции. |
| `pages.lock.json` | Список страниц справочника, по которым собран снимок: идентификатор, название, группа и SHA-256 текста страницы. |
| `update_spec.py` | Сверка справочника со списком страниц и черновик операций из страниц. |
| `test_update_spec.py`, `test_spec.py` | Офлайн-тесты скрипта и согласованности снимка с дополнением. |

## Откуда снимок

Справочник Huawei: раздел «Connect API» каталога
[AppGallery-connect-References](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-obtain_token-0000001158365043)
(токены, Publishing API, Upload Management API, Reports API, Project Management API,
Comments API, PMS API, приложения) и раздел «AppGallery Connect API» каталога
[app](https://developer.huawei.com/consumer/en/doc/app/agc-help-connect-api-introduction-0000002270974725)
(Provisioning API и новая редакция Upload Management API). Remote Configuration — раздел
«Remote Configuration / Server / REST API» каталога AppGallery-connect-References: разделов
с названием «REST API» в каталоге несколько, поэтому корень источника в `update_spec.py`
задан путём через ` / ` (последние имена предков узла).
Серверный REST API App Linking — раздел «App Linking / Server / REST» того же каталога:
две операции и коды результата.
Серверные API покупок в приложении — раздел «Server» раздела In-App Purchases каталога
[HMSCore-References](https://developer.huawei.com/consumer/en/doc/development/HMSCore-References/api-common-statement-0000001050986127)
(сервис заказов и сервис подписок HMS IAP).
REST API IAP Kit для HarmonyOS 5 и новее — раздел «IAP Kit / REST API» каталога
[harmonyos-references](https://developer.huawei.com/consumer/en/doc/harmonyos-references/iap-rest-common-statement):
его операции (группа `iapkit`) лежат в снимке только для поиска и исключены с
`callable = false` (пункт 31 ниже).

Портал документации отдаёт дерево разделов и страницы в JSON без авторизации:

- дерево: `POST https://svc-drcn.developer.huawei.com/community/servlet/consumer/cn/documentPortal/getCatalogTree`,
  тело `{"language":"en","catalogName":"<каталог>","objectId":"<любая страница каталога>"}`;
- страница: `POST .../documentPortal/getDocumentById`, тело `{"language":"en","objectId":"<id страницы>"}`,
  HTML страницы — в `value.content.content`.

Снимок не копирует справочник: описания операций написаны заново и коротко, описания
полей сокращены. За подробностями инструмент отсылает на страницу справочника
(`x-agc-reference`).

## Снимок `openapi.json`

- Хост один условный — `https://connect-api.cloud.huawei.com`; настоящий хост выбирается
  регионом профиля. Пути — от корня хоста и начинаются с `/api/`. Исключение — операции
  HMS IAP (`x-agc-service`): у них свой хост сайта (`orders-*`, `subscr-*`), путь от его
  корня без `/api/` и без параметров пути, а справочник пишет адрес как `{rootUrl}/…`.
- `operationId` — `<группа>.<ресурс>.<действие>`, например `publishing.appInfo.get`.
  Первая часть совпадает с `x-agc-group`.
- `summary` — первое предложение, `description` начинается с него и добавляет важные
  ограничения. Тексты на английском.
- Параметры — `in: path | query | header`. Заголовки авторизации (`client_id`,
  `Authorization`, а для режима OAuth-клиента `teamId` и `oauth2Token`) в параметры не
  входят: их добавляет исполнитель запросов. Остальные заголовки — обычные параметры
  `in: header` (`appId` у PMS API, `requestId` у ответа на отзыв, `userID` и `uid` у
  Project Management API, `appId` и `provisionId` у списка профилей). Параметр-массив
  есть только в строке запроса и передаётся повтором имени (`style: form`,
  `explode: true`).
- Тело запроса — всегда `application/json`, схема — объект. Общие модели лежат в
  `components/schemas`. Рядом с `$ref` допустим только `description` (описание поля);
  генератор подставляет схему по ссылке и сохраняет это описание.
- Ответ `200` — объект с конвертом результата и данными.

Расширения:

| Расширение | Где | Смысл |
| --- | --- | --- |
| `x-agc-group` | операция | Группа API: `auth`, `publishing`, `upload`, `reports`, `comments`, `pms`, `project`, `provisioning`, `remoteconfig`, `applinking`, `orders`, `subscriptions`, `iapkit`. Названия и адреса групп — в `[[groups]]` дополнения. |
| `x-agc-result` | операция | Конверт результата: `field` — поле ответа с объектом результата, `codeField` — поле кода в нём (успех — `0`), `messageField` — поле текста. Ответ с HTTP 200 и ненулевым кодом — ошибка. |
| `x-agc-auth-modes` | операция | Режимы авторизации, для которых справочник описывает операцию: `api-client`, `oauth-client`, `service-account`. Нет расширения — страница режимов не называет. |
| `x-agc-reference` | операция | Адрес страницы операции в справочнике. |
| `deprecated` | операция, параметр, поле | Справочник называет операцию, параметр или поле устаревшими. |
| `x-agc-external-operations` | корень документа | Запросы, которые справочник описывает как операции, но которые не являются вызовами Connect API: отправка файла или фрагмента файла на адрес из ответа API. Ключ — идентификатор операции; поля — `method`, `summary`, `description`, `x-agc-group`, `x-agc-reference` и `x-agc-url-source` (операция, ответ которой даёт адрес и заголовки). Пути у них нет. |
| `x-agc-title` | тег | Название раздела справочника. |
| `x-agc-service` | операция | Сервис, на хост которого уходит запрос: `iap-orders` (сервис заказов HMS IAP) или `iap-subscriptions` (сервис подписок). Нет расширения — AppGallery Connect API. Операции сервиса подписываются токеном уровня приложения, генератор сам добавляет им аргумент `appId`, который выбирает секрет приложения и в запрос не уходит; `api_request` их не вызывает. `iap-kit` — REST API IAP Kit (HarmonyOS 5+, хост `iap.cloud.huawei.com`): генератор требует, чтобы такие операции были в `[[exclude]]` с `callable = false`, исполнитель их отклоняет. |
| `x-agc-json` | свойство схемы ответа | Поле — строка с JSON внутри (`purchaseTokenData`, `inappPurchaseData`, `cancelledPurchaseList` у HMS IAP); значение расширения — схема разобранного значения. Сервер отдаёт агенту разобранное значение. Допустимо только у свойства-строки. |

Конверты результата:

| Группы | `x-agc-result` |
| --- | --- |
| `auth`, `publishing`, `upload`, `reports`, `project`, `provisioning`, `remoteconfig`, `applinking` | `ret` / `code` / `msg` |
| `comments` | `ret` / `rtnCode` / `rtnDesc` |
| `pms` | `error` / `errorCode` / `errorMsg` |
| `orders`, `subscriptions` (HMS IAP) | `""` / `responseCode` / `responseMessage`: код (строка, успех — `"0"`) и текст в корне тела |
| `iapkit` (IAP Kit, не вызывается) | `""` / `responseCode` / `responseMessage`; у ответа о возврате — `""` / `returnCode` / `returnDesc` |

Что в снимок не вошло:

- «Obtaining the Callback Result» (Publishing API) — это обратный вызов Huawei на адрес
  разработчика, а не операция API;
- «Obtaining a Project-Level Token» — тот же `POST /api/oauth2/v1/token`, что и обычное
  получение токена: в снимке одна операция `auth.token.create`;
- модели данных, приложения (языки, страны, категории, ограничения файлов, правила цен)
  и коды результата — отдельные страницы справочника; модели разобраны в
  `components/schemas`, остальное остаётся в справочнике.

Upload Management API описан в справочнике дважды. Снимок следует редакции каталога
References: она шире (в инициализации загрузки по частям есть `fileType` и `obbType`).

## Дополнение `overlay.toml`

Операции называются по `operationId` снимка, внешние операции — по ключу в
`x-agc-external-operations`. Тексты `description`, `reason` и `alternative` — для агента,
на английском.

| Раздел | Ключи | Смысл |
| --- | --- | --- |
| `[[groups]]` | `slug`, `title`, `reference` | Группы API в порядке вывода: название раздела справочника и его адрес. Группы снимка и дополнения должны совпадать. |
| `[[toolsets]]` | `slug`, `description`, `default`, `operations` | Наборы инструментов в порядке вывода. `default` — включён ли набор по умолчанию (без ключа — нет). Каждая операция входит ровно в один набор. |
| `[names]` | `"<operationId>" = "<имя>"` | Имя инструмента: «глагол_ресурс», snake_case, не длиннее 40 символов, уникальное. Задаётся для каждой операции, которая не исключена. |
| `[[access]]` | `level`, `reason`, `operations` | Исключения из уровня доступа. `level` — `read`, `write` или `destructive`; `reason` попадает в описание инструмента. |
| `[[exclude]]` | `operations`, `reason`, `alternative`, `callable` | Операции, которые не становятся инструментами. `reason` — почему, `alternative` — что вызвать вместо. `callable = false` запрещает вызов и через `api_request` (без ключа — `true`). |
| `[[deprecated]]` | `operation`, `replacement`, `note` | Замены для устаревших операций (сейчас раздела нет: устаревших операций в справочнике нет). Операция с `deprecated: true` в снимке исключается сама. |
| `[[secrets]]` | `kind`, `description`, `hint`, `operations`, `fields` | Поля ответов с секретами. `kind` — `credential` (учётные данные: агенту не отдаются), `download-url` (временная ссылка на файл) или `file-content` (содержимое файла с учётными данными); для двух последних у инструмента есть `save_to`, и у операции такое поле может быть только одного вида. `fields` — пути в JSON ответа через `.`, `[]` — каждый элемент массива; поле должно быть в схеме ответа `200` и быть строкой. `description` и `hint` попадают в пометку `note` агенту. |
| `[[project_credentials]]` | `groups`, `operations`, `param` | Операции, которые сервер подписывает API-клиентом проекта, а не команды (серверные API сервисов проекта). `param` — обязательный параметр пути, запроса или заголовка с Project ID; без него генератор берёт единственный из `productId` и `projectId`. У операции не должно быть `x-agc-auth-modes` без `api-client`; исключённую операцию пометить нельзя. В описание инструмента добавляется, что нужен API-клиент проекта. Сейчас помечены группы `remoteconfig` и `applinking` (заголовок `productId`). |
| `[[omit]]` | `reason`, `operations`, `fields` | Поля ответов, которые сервер убирает из ответа агенту, с причиной для агента (в пометке `note` и в описании инструмента). Пути — как у `[[secrets]]`; поле должно быть строкой схемы ответа и не может быть секретным или строкой с JSON. Сейчас — подпись данных покупки HMS IAP (`dataSignature`, `signatureAlgorithm`): после разбора JSON-строки её не проверить. |

Уровень доступа по умолчанию задаёт HTTP-метод: `GET` — чтение, `DELETE` — удаление,
остальное — запись. Исключения:

- удаление (`destructive`) — действия с последствиями для пользователей AppGallery и
  денег: отправка на проверку (обычная и в режиме скачивания), изменение поэтапного
  выпуска и времени выпуска, публичный ответ на отзыв, изменение товаров и цен,
  активация и деактивация товаров, создание, изменение, запуск и снятие акций, удаление
  сертификатов и устройств запросом `POST`, запись новой версии Remote Configuration
  (`PUT`) и откат к прежней (`POST`): они сразу действуют для пользователей приложения;
  у HMS IAP — подтверждение доставки товара, отмена, отсрочка оплаты, возврат платежа и
  отзыв подписки;
- запись (`write`) — `GET`, который выдаёт адрес и заголовки для загрузки файла;
- чтение (`read`) — `POST`, который только читает: поиск товаров, акций, групп подписок,
  список сертификатов, у HMS IAP — проверка токена покупки и подписки, списки отменённых
  покупок и заказов.

Создание ссылок App Linking (`POST`) — запись по методу: ссылка публичная, но приложение,
его страницу и пользователей не меняет. Удаления ссылок в API нет, поэтому уровня удаления
в группе нет; что ссылки не видны в консоли и не удаляются через API, сказано в описании
операций снимка.

Изменение данных приложения, локализаций и файлов до отправки на проверку — запись.

Вне наборов могут быть только исключённые операции с `callable = false` (получение
токена). Ошибки, на которых должна падать сборка: операция без набора или в двух
наборах, операция без имени, повтор имени, имя длиннее 40 символов, ссылка на
несуществующую операцию или группу, исключение из уровня доступа, совпадающее с уровнем
по умолчанию, неизвестные ключи. Те же правила проверяет `test_spec.py`.

Внешние операции в таблицы операций не попадают: они должны быть исключены с
`callable = false` и не получают имени инструмента. `reason` исключения становится
пояснением исключённой операции, `alternative` — подсказкой, что вызвать вместо неё.

Шаги загрузки Upload Management API (получение адреса загрузки и загрузка по частям)
тоже исключены с `callable = false`, но остаются в наборе `releases`: их ответы целиком
состоят из одноразовых адресов и заголовков загрузки, а файл загружает составной
инструмент загрузки.

Запрос сертификата Provisioning API (`provisioning.cert.create`) исключён так же
(`callable = false`, набор `provisioning`): он принимает запрос на подпись (CSR) строкой
в теле, а сервер берёт CSR только из локального файла. Его вызывает составной
`certificate_request`: читает файл, проверяет форму PEM, отклоняет файлы с приватным
ключом и сохраняет файл сертификата по ссылке из ответа (`save_to`). У исключённой
операции нет `[[secrets]]`, поэтому поле ссылки (`certInfo.certDownloadUrl`) составной
инструмент убирает из ответа сам; то же имя поля скрывается и по имени, потому что оно
указано в `[[secrets]]` списка сертификатов. Остальные операции набора — инструменты;
удаление сертификатов, устройств и профилей — уровень удаления (у `POST`-удалений
сертификатов и устройств причина в `[[access]]`, у `DELETE` профиля — в описании
операции: исключение, совпадающее с уровнем по методу, запрещено).

## Обновление

```sh
python3 -I crates/appgallery-connect-api/spec/update_spec.py --check        # только отчёт
python3 -I crates/appgallery-connect-api/spec/update_spec.py --draft DIR    # страницы и черновик
python3 -I crates/appgallery-connect-api/spec/update_spec.py --lock         # записать pages.lock.json
```

Раздел справочника задаётся корневым узлом дерева (`Source.root` в скрипте); путь через
` / ` (`App Linking / Server / REST`) — узел с этими именами ближайших предков: узлы «Server»
и «REST» есть у многих сервисов. Дерево каталога скачивается один раз за прогон, даже если
разделов в каталоге несколько.

Скрипт (Python 3.10+, только стандартная библиотека) обращается только к порталу
документации Huawei, к самому AppGallery Connect API он не ходит. Запросы идут по одному,
с паузой 0,4 с; таймаут 45 с, до четырёх попыток с паузами 5, 15 и 30 с (не меньше
`Retry-After`, но не больше минуты) при сбое сети, таймауте, `408`, `429`, `5xx` и ответе
без дерева или без текста страницы. Другой ответ `4xx` не повторяется. Страниц около 190,
полный проход занимает несколько минут; общий лимит времени на загрузку — 15 минут
(`--time-limit SECONDS`, `0` — без лимита).

- `--check` скачивает дерево и страницы, считает SHA-256 и сравнивает с
  `pages.lock.json`. Печатает изменённые, новые и пропавшие страницы, а также страницы,
  которые переименованы или перенесены в другой раздел без изменения текста. Ничего не
  записывает.
- `--draft DIR` сохраняет ответы портала в `DIR/pages/` и `DIR/tree.<каталог>.json` и
  пишет `DIR/draft.json` — черновик для ручной правки снимка:
  - `operations` — страницы с прототипом: метод, путь, параметры по расположению
    (`path`, `query`, `header`, `body`) с обязательностью, типом и описанием, вложенные
    таблицы моделей (`nestedTables`), поля ответа, примеры запроса и ответа, конверт
    результата (`result`, с пометкой `source`: из примера или из таблицы), режимы
    авторизации, адрес страницы и `notes` — расхождения, найденные при разборе (параметр
    есть в URL, но не в таблице; параметр в примере написан иначе; конверт не определён);
  - `external` — страницы с методом, но без адреса Connect API (отправка файла на адрес
    из ответа, обратный вызов);
  - `models` — страницы моделей данных с таблицей полей;
  - `other` — остальные страницы (обзоры, коды результата, приложения).
- `--lock` записывает `pages.lock.json` по текущим страницам.
- `--from-dir DIR` вместо сети читает дерево и страницы из каталога, заполненного
  `--draft`: так `--lock` и повторный `--draft` не скачивают страницы заново.
- `--lock-file FILE` — другой путь к списку страниц; `--quiet` — без хода загрузки
  (повторы и итог — число страниц и время — печатаются всё равно).

Хеш считается по нормализованному тексту страницы: заголовки, абзацы, строки таблиц и
примеры кода без разметки. Идентификаторы элементов, классы, якоря и ширина колонок в
него не входят, поэтому перевёрстка страницы не считается изменением.

Коды выхода:

| Код | Когда |
| --- | --- |
| `0` | Расхождений нет или файл записан. |
| `1` | Другая ошибка: не читается `pages.lock.json` или файл из `--from-dir`, портал ответил `4xx` (кроме `408` и `429`) — скорее всего, изменился сам портал документации, и повтор не поможет. |
| `2` | Неверные аргументы. |
| `3` | `--check` нашёл расхождения: изменённые, новые, пропавшие или переименованные страницы, либо в дереве нет корневого узла раздела. |
| `4` | Портал недоступен после повторов (сеть, таймаут, `408`, `429`, `5xx`, ответ без содержимого) или вышел общий лимит времени. Справочник не сверен: проверку повторяют позже. |

Отчёт `--check` (stdout) начинается со сводки «изменено N, новых N, пропало N,
переименовано или перенесено N», дальше — страницы по разделам: группа, название и адрес
страницы в справочнике.

Раз в неделю `--check` запускает CI по расписанию (workflow `spec-drift`, Linux, только
Python). Код `3` и код `4` красят прогон; при коде `4` в логе сказано, что справочник не
сверен из-за портала.

Каталог с черновиком и скачанными страницами в репозиторий не добавляется.

Порядок работы, когда `--check` нашёл изменения:

1. `--draft DIR`, затем посмотри изменённые и новые страницы в `DIR/draft.json` и в
   справочнике;
2. поправь `openapi.json` вручную. Черновик — подспорье, а не источник истины:
   справочник местами неточен, и исправления по итогам живой сверки не должны затираться;
3. для новой операции добавь набор и имя в `overlay.toml`, проверь уровень доступа по
   правилам выше; для пропавшей — убери её из дополнения;
4. `--lock --from-dir DIR`;
5. запусти тесты и сборку крейта, просмотри изменения снапшотов операций.

Тесты (без сети):

```sh
python3 -I -B -m unittest discover -s crates/appgallery-connect-api/spec -p 'test_*.py'
```

`test_update_spec.py` проверяет разбор страниц, нормализацию и сравнение списков на
выдуманных фрагментах HTML, а также повторы, лимит времени, отчёт и коды выхода — с
подменённой загрузкой, паузой и часами. `test_spec.py` проверяет снимок и дополнение: у
каждой операции есть группа, конверт результата, набор и имя либо исключение; имена уникальны и
не длиннее 40 символов; все `$ref` разрешаются; пути начинаются с `/api/` (у HMS IAP — без
`/api/`, с корневым конвертом `responseCode`); дополнение не
ссылается на несуществующие операции; страницы операций есть в `pages.lock.json`. Для
`test_spec.py` нужен Python 3.11+ (`tomllib`), на 3.10 он пропускается.

## Что проверить живой сверкой

Снимок собран только по справочнику, к API никто не обращался. Места, где справочник
противоречит сам себе или вызывает сомнения:

1. **Project Management API и режим API-клиента.** Все восемь операций группы `project`
   описаны только для режима OAuth-клиента (списки команд и приложений, отпечатки) или
   для OAuth-клиента и Service Account (проекты, сервисы, файл конфигурации). Работают ли
   они с токеном API-клиента — неизвестно (`x-agc-auth-modes`).
2. **Регистр `appId` в Comments API.** В таблицах параметров — `appId`, в примерах
   запросов списка отзывов и одного отзыва — `appid`. В снимке `appId`.
3. **`ratings` или `rating`.** У списка оценок в таблице параметр `ratings`, а в адресе
   прототипа — `rating`. В снимке `ratings`.
4. **Конверт без примера ответа.** У Reports API, Project Management API, получения
   адреса загрузки, инициализации и склейки загрузки по частям, списка пакетов и отправки
   пакета по ссылке нет примера ответа. Конверт `ret.code` / `ret.msg` взят из таблицы
   параметров, где `ret` местами назван строкой с JSON внутри. Нужно убедиться, что `ret`
   приходит объектом и что поля называются `code` и `msg`.
5. **Ошибка получения токена.** По таблице при ошибке приходит `ret` с кодом при HTTP 200;
   примера нет.
6. **Опечатка в путях.** `/api/cds/app-distirbution/v1/all/...` — так в справочнике (три
   операции группы `project`).
7. **Список сертификатов.** В таблице ответа поле называется `certInfo`, в примере —
   `certList`. В снимке оба; нужно узнать, какое приходит на самом деле.
8. **Список профилей.** `appId` и `provisionId` по справочнику передаются заголовками, хотя
   это `GET` со строкой запроса. В снимке — заголовки. Текст страницы называет только
   режимы API-клиента и OAuth-клиента, а таблицы заголовков — все три режима; в снимке
   три.
9. **Тело отправки на проверку.** У `publishing.app.submit` поля поэтапного выпуска лежат
   в корне тела и помечены обязательными, хотя нужны только при `releaseType=3`. В снимке
   тело необязательно, поля необязательны.
10. **Заголовки загрузки фрагмента.** У `FilePartUploadInfo.headers` в таблице тип — строка,
    в примере — объект. В снимке объект.
11. **Создание товаров и групп.** Отдельных операций создания товара и группы подписок в
    справочнике нет; по описаниям полей похоже, что их создают операции обновления
    (`pms.product.update`, `pms.product.batchUpdate`, `pms.productGroup.update`). От этого
    зависит и уровень доступа обновления группы (сейчас запись).
12. **Удаление локализации.** `publishing.languageInfo.delete` получает уровень удаления по
    методу `DELETE`. Если удаление меняет только черновик версии до отправки на проверку,
    уровень можно понизить до записи.
13. **`appID` и `appId`.** У `project.service.list` параметр называется `appID` и имеет
    целый тип, в ответе `project.appBriefInfo.list` поле — `appID`, в остальных местах —
    `appId` строкой.
14. **Отметки времени в Comments API.** Справочник описывает `beginTime` и `endTime` как
    миллисекунды «с 1970-01-01 08:00:00»; скорее всего это обычное время Unix.
15. **Ответы с секретами и временными ссылками.** `project.appExtraInfo.get` возвращает
    секрет приложения, `project.configFile.get` — файл конфигурации целиком, операции
    Reports API — временную ссылку на файл, операции сертификатов и профилей — временные
    ссылки на скачивание (у запроса сертификата ссылку убирает составной
    `certificate_request`). Эти поля перечислены в `[[secrets]]` и скрываются по именам
    из снимка; при живой сверке нужно проверить, что настоящие ответы называют поля так же
    (`secret`, `content`, `fileURL`, `certDownloadUrl`, `provisionDownloadUrl`), что
    `content` — текст файла, а не ссылка, и что ссылки ведут на хосты Huawei.
16. **Две редакции Upload Management API.** В новой редакции (каталог `app`) у
    инициализации загрузки по частям нет `fileType` и `obbType`, а описание ограничено
    пакетами HarmonyOS. Нужно проверить, что параметры старой редакции принимаются.
17. **Provisioning API целиком.** Кабинета с приложением HarmonyOS при сборке снимка не
    было, ни одна операция набора `provisioning` не вызывалась. На таком кабинете
    проверить:
    - какую роль API-клиента требует Provisioning API и отвечает ли `list_devices`
      клиенту без неё ошибкой доступа (HTTP 403 или код в `ret`);
    - в каком виде принимается `csr`: блок PEM с переводами строк `\n` (так шлёт
      `certificate_request`) или одной строкой, с заголовком `NEW CERTIFICATE REQUEST`
      (DevEco Studio) и `CERTIFICATE REQUEST` (OpenSSL); считаются ли переводы строк в
      лимит 2048 символов;
    - принимает ли список сертификатов пустое тело `{}` и сужает ли `certIds` выдачу до
      одного сертификата (на этом держится `save_to` списка);
    - на каких хостах лежат файлы по `certDownloadUrl` и `provisionDownloadUrl` (в примерах
      хост скрыт; если это не `*.huawei.com`, `*.hicloud.com`, `*.myhuaweicloud.com` или
      `*.dbankcloud.*`, скачивание будет отклонено), сколько живут ссылки и что файлы —
      `.cer` и `.p7b`, а не JSON или base64;
    - что `provisionDownloadUrl` есть и в ответе списка профилей, а `deviceList` профиля
      и `aclPermissionList` приходят как в справочнике;
    - что удаление сертификата, которым подписан профиль, отклоняется или делает профиль
      недействительным, и что удаление устройства, привязанного к профилю, даёт код
      `204144769` («устройства используются»);
    - удаление профиля: `DELETE /api/publish/v2/provision?id=…` (`v2`, хотя создание и
      список — `v3`), повторное удаление и удаление чужого профиля;
    - тип времени: у `CertInfo` и `ProvisionInfo` — число (мс), у `DeviceInfo.createTime` —
      строка `yyyy-MM-dd HH:mm:ss.SSS`;
    - коды результата со страницы Result Codes (`204144641` и дальше) и приходят ли они в
      `ret.code` при HTTP 200.
18. **Remote Configuration.** Операции группы `remoteconfig` не вызывались: нужен проект
    с Remote Configuration и API-клиент проекта (Project settings → Server SDK). Проверить:
    - заменяет ли `PUT /api/remote-config/v1/config` конфигурацию целиком или сливает
      переданное с текущим: `remote_config_set` отправляет все параметры и условия, а
      удаление делает пропуском, и на этом держится удаление;
    - приходит ли `ret` объектом с `code` и `msg` при HTTP 200 и какие HTTP-статусы
      бывают у кодов `204079106`, `204079107`, `204079109`, `204083201` (версию успели
      изменить), `204083203`;
    - какой номер версии у проекта без конфигурации (сервер считает `0`), есть ли тогда
      `versionInfo` и принимает ли `PUT` версию `0`;
    - создаёт ли откат новую версию (с новым номером) или делает текущей старую, и какой
      `version` после отката ждёт `PUT`;
    - поля условий, которых нет в модели справочника (`audiences`, `userAttributes`,
      `predictions` в примере ответа): принимает ли их `PUT` обратно без изменений;
    - нужен ли в теле `PUT` `appName` и в каком виде заголовок `appId` (строка или
      число); привязан ли `productId` к проекту приложения `appId`;
    - какие роли API-клиента проекта нужны (справочник называет Administrator, App
      administrator, Development, Operations) и что приходит без них;
    - на каком хосте работает клиент проекта, если место хранения данных проекта не
      совпадает с регионом профиля;
    - как быстро устройства получают новую версию и действует ли лимит 5 запросов в
      секунду и 1000 в час на IP-адрес на все операции группы вместе;
    - единицы `userRatio.value` (в справочнике доля, умноженная на 10⁸: 2 % — `2000000`)
      и формат `DateTimeCond.timeZone`.
19. **App Linking.** Ни одна операция группы `applinking` не вызывалась. На тестовом проекте
    с API-клиентом проекта и заведённым префиксом ссылок проверить:
    - что запрос с клиентом команды (Project = N/A) действительно отклоняется, а с клиентом
      проекта проходит; каким кодом или статусом отвечает чужой `productId`;
    - тип `openType`, `previewType` и `landingPageType`: в таблице — `int`, в примере
      запроса `openType` — строка `"1"`. В снимке целые; если API принимает только строки,
      поправить тип;
    - `expireTime`: в таблице `Long` в секундах, «больше 300»; что приходит при 300 и меньше
      (код `204865608`?) и как ведут себя ссылки с истёкшим сроком;
    - `suffixLength` — строки `SHORT` и `LONG`, как в таблице (в клиентских SDK это
      перечисление `ShortAppLinking.LENGTH`);
    - что `ret` приходит объектом `{code, msg}` (в таблице ответа он назван строкой с JSON);
    - что созданные через API ссылки действительно не видны в консоли и что удалить их
      нельзя никак (тогда описание операций остаётся как есть);
    - обязательность полей единой ссылки (`uriPrefix`, `name`, `defaultRedirectionUrl`):
      сервер её внутри `body` не проверяет, решает API;
    - хост для проектов с местом обработки данных вне Китая: справочник требует, чтобы
      токен и запрос шли на один хост; сервер берёт оба по региону профиля.

### Вход пользователя (режим OAuth-клиента)

Источник — раздел OAuth Client Mode страницы Getting Started справочника Connect API и
документация HUAWEI ID (Account Kit) о веб-входе с PKCE. С настоящим HUAWEI ID вход не
проверялся. Решения, принятые по самому правдоподобному варианту:

20. **Адрес возврата.** Неизвестно, принимает ли HUAWEI ID любой порт loopback-адреса
    (`http://127.0.0.1:<случайный порт>/`) или только адрес, указанный у приложения.
    По умолчанию используется случайный порт, `--redirect-uri` задаёт постоянный.
21. **Где создаётся OAuth-клиент.** Отдельной вкладки OAuth client в Users and permissions
    → API key справочник не показывает. Подсказка CLI предлагает приложение с HUAWEI ID
    (Account Kit) в AppGallery Connect или в HUAWEI Developers Console.
22. **Секрет при PKCE.** Нужен ли `client_secret` при обмене кода и обновлении, если есть
    `code_verifier`. Секрет отправляется, когда он задан (`client_secret_post`); без
    секрета запрос идёт только с `client_id`.
23. **Ротация refresh token.** Выдаёт ли HUAWEI ID новый refresh token при обновлении.
    Если выдаёт, сервер и CLI сохраняют его в хранилище.
24. **Заголовки запросов.** Справочник называет для этого режима `oauth2Token` (без
    `Bearer`) и `teamId`. Нужен ли рядом `Authorization`, неизвестно; сейчас его нет.
25. **Список команд.** Нужна ли для `user-team-list` область `project`. Отдаёт ли хост
    `cn` команды всех сайтов, или список нужно запрашивать на хосте сайта команды. Сейчас
    запрос идёт на хост явного или сохранённого региона, иначе `cn`. Принимает ли сервер
    `teamId` там, где в справочнике указан только `oauth2Token`.
26. **Неодобренные области.** Отказывает ли HUAWEI ID во входе, если Huawei ещё не одобрил
    запрошенные области, или выдаёт токен без них. CLI предупреждает, если выданы не все
    запрошенные области.
27. **Ошибка входа во фрагменте.** HUAWEI ID сообщает об отказе во фрагменте адреса
    (`#error=…`), который loopback-сервер не получает. Сервер показывает страницу без кода и
    ждёт до таймаута. Нужно проверить, не приходит ли ошибка в query.
28. **`userID` у `project.appBriefInfo.list`.** По справочнику это заголовок, обязательный
    в этом режиме. Сейчас его передаёт агент как обычный параметр. Если это ID
    вошедшего пользователя, сервер мог бы подставлять его сам.
29. **Сроки.** Access token — час (`expires_in` 3600), refresh token — 180 дней, код входа —
    5 минут. Отзыв — `oauth2/v3/revoke` с `token=<refresh token>`.

### Покупки в приложении (HMS IAP)

30. **HMS IAP (набор `purchases`, группы `orders` и `subscriptions`).** Ни одна операция
    не вызывалась: нужен кабинет с приложением, у которого включён In-App Purchases, и
    тестовые покупки в песочнице. Проверить:
    - префикс в заголовке `Authorization`: текст справочника говорит `APPAT:`, а пример
      запроса проверки токена кодирует `AT:` (сервер шлёт `APPAT:`);
    - срок жизни токена приложения (`expires_in`), есть ли у сайта России свой хост OAuth
      вместо `oauth-login.cloud.huawei.com` и совпадает ли client ID приложения с App ID;
    - что хост сервисов заказов и подписок выбирается по сайту профиля (`orders-drru`,
      `subscr-drru` и т. д.), а не по стране покупателя или месту хранения данных
      приложения;
    - `responseCode` приходит строкой (`"0"`), а ошибки — с HTTP 200; что приходит при
      неверном токене приложения (HTTP 401 или код в теле);
    - пример ответа подтверждения покупки в справочнике — невалидный JSON (нет запятой);
      настоящий ответ должен разбираться;
    - `newExpirationTime` у отсрочки: в таблице — число, в примере — строка;
    - типы в данных покупки: `price` и `payType` в примерах то строкой, то числом,
      `applicationId` — числом;
    - что `purchaseTokenData`, `inappPurchaseData` и `cancelledPurchaseList` — строки с
      JSON (на этом держится их разбор) и что без `HW-IAP-APPINFO` подпись ответа
      `SHA256WithRSA` (сервер её всё равно убирает);
    - покупки в песочнице: возвращаются ли они в `list_cancelled_purchases` и
      `list_iap_orders`, и `purchaseType` 0 в данных покупки;
    - что `confirm_product_purchase` подтверждает и нерасходуемые товары, а не только
      расходуемые, и что повторное подтверждение даёт код `9`.
    - что токен приложения принимается и у кабинета, с которым сервер работает от имени
      пользователя (профиль OAuth-клиента): справочник IAP режимов Connect API не называет,
      и `x-agc-auth-modes` у операций IAP нет, поэтому сервер подписывает их токеном
      приложения при любом способе входа профиля.

### IAP Kit для HarmonyOS 5 и новее

31. **REST API IAP Kit (группа `iapkit`).** Одиннадцать операций справочника (статус заказа и
    подписки, подтверждение доставки, отсрочка продления, заказы за период, поиск по номеру
    заказа, история покупок пользователя, записи и проверка уведомлений, ответ на запрос
    возврата) лежат в снимке по таблицам справочника, но исключены с `callable = false`:
    `api_search` их находит и объясняет, что сервер их не вызывает. Чтобы их включить,
    нужно:
    - хранить ключ IAP Kit профиля: закрытый ключ `.p8` (EC P-256), Key ID и Issuer ID из
      AppGallery Connect («Configuring the Key»), запись хранилища и команду CLI вроде
      `auth iap-key set`;
    - подписывать каждый запрос JWT ES256: заголовок `alg`, `typ`, `kid`; тело `iss`,
      `aud = "iap-v1"`, `iat`, `exp` (не больше часа после `iat`), `aid` (App ID из
      аргумента `appId`) и `digest` — SHA-256 в hex от точной строки тела запроса (тело
      нужно сериализовать один раз и отправить те же байты; у пустого тела — хеш пустой
      строки); заголовок `Authorization: Bearer <JWT>`;
    - проверять поля ответа в формате JWS (`jwsPurchaseOrder`, `jwsSubGroupStatus`,
