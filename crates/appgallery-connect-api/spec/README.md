# Спецификация AppGallery Connect API

У Huawei нет машинной спецификации Connect API: есть только страницы справочника.
MCP-инструменты операций генерируются при сборке из двух файлов, которые мы ведём сами:

| Файл | Что это |
| --- | --- |
| `openapi.json` | Снимок API в формате OpenAPI 3.0: операции, параметры, тела запросов, ответы. Собран по страницам справочника и правится вручную. |
| `overlay.toml` | Файл-дополнение: всё, чего нет в справочнике, — группы, наборы инструментов, имена инструментов, уровни доступа, исключённые операции. |
| `pages.lock.json` | Список страниц справочника, по которым собран снимок: идентификатор, название, группа и SHA-256 текста страницы. |
| `update_spec.py` | Сверка справочника со списком страниц и черновик операций из страниц. |
| `test_update_spec.py`, `test_spec.py` | Офлайн-тесты скрипта и согласованности снимка с дополнением. |

## Откуда снимок

Справочник Huawei: раздел «Connect API» каталога
[AppGallery-connect-References](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-obtain_token-0000001158365043)
(токены, Publishing API, Upload Management API, Reports API, Project Management API,
Comments API, PMS API, приложения) и раздел «AppGallery Connect API» каталога
[app](https://developer.huawei.com/consumer/en/doc/app/agc-help-connect-api-introduction-0000002270974725)
(Provisioning API и новая редакция Upload Management API).

Портал документации отдаёт дерево разделов и страницы в JSON без авторизации:

- дерево: `POST https://svc-drcn.developer.huawei.com/community/servlet/consumer/cn/documentPortal/getCatalogTree`,
  тело `{"language":"en","catalogName":"<каталог>","objectId":"<любая страница каталога>"}`;
- страница: `POST .../documentPortal/getDocumentById`, тело `{"language":"en","objectId":"<id страницы>"}`,
  HTML страницы — в `value.content.content`.

Снимок не копирует справочник: описания операций написаны заново и коротко, описания
полей сокращены. За подробностями инструмент отсылает на страницу справочника
(`x-agc-reference`).

## Снимок `openapi.json`

- Хост один условный — `https://connect-api.cloud.huawei.com`; настоящий хост выбирается
  регионом профиля. Пути — от корня хоста и начинаются с `/api/`.
- `operationId` — `<группа>.<ресурс>.<действие>`, например `publishing.appInfo.get`.
  Первая часть совпадает с `x-agc-group`.
- `summary` — первое предложение, `description` начинается с него и добавляет важные
  ограничения. Тексты на английском.
- Параметры — `in: path | query | header`. Заголовки авторизации (`client_id`,
  `Authorization`, а для режима OAuth-клиента `teamId` и `oauth2Token`) в параметры не
  входят: их добавляет исполнитель запросов. Остальные заголовки — обычные параметры
  `in: header` (`appId` у PMS API, `requestId` у ответа на отзыв, `userID` и `uid` у
  Project Management API, `appId` и `provisionId` у списка профилей). Параметр-массив
  есть только в строке запроса и передаётся повтором имени (`style: form`,
  `explode: true`).
- Тело запроса — всегда `application/json`, схема — объект. Общие модели лежат в
  `components/schemas`. Рядом с `$ref` допустим только `description` (описание поля);
  генератор подставляет схему по ссылке и сохраняет это описание.
- Ответ `200` — объект с конвертом результата и данными.

Расширения:

| Расширение | Где | Смысл |
| --- | --- | --- |
| `x-agc-group` | операция | Группа API: `auth`, `publishing`, `upload`, `reports`, `comments`, `pms`, `project`, `provisioning`. Названия и адреса групп — в `[[groups]]` дополнения. |
| `x-agc-result` | операция | Конверт результата: `field` — поле ответа с объектом результата, `codeField` — поле кода в нём (успех — `0`), `messageField` — поле текста. Ответ с HTTP 200 и ненулевым кодом — ошибка. |
| `x-agc-auth-modes` | операция | Режимы авторизации, для которых справочник описывает операцию: `api-client`, `oauth-client`, `service-account`. Нет расширения — страница режимов не называет. |
| `x-agc-reference` | операция | Адрес страницы операции в справочнике. |
| `deprecated` | операция, параметр, поле | Справочник называет операцию, параметр или поле устаревшими. |
| `x-agc-external-operations` | корень документа | Запросы, которые справочник описывает как операции, но которые не являются вызовами Connect API: отправка файла или фрагмента файла на адрес из ответа API. Ключ — идентификатор операции; поля — `method`, `summary`, `description`, `x-agc-group`, `x-agc-reference` и `x-agc-url-source` (операция, ответ которой даёт адрес и заголовки). Пути у них нет. |
| `x-agc-title` | тег | Название раздела справочника. |

Конверты результата:

| Группы | `x-agc-result` |
| --- | --- |
| `auth`, `publishing`, `upload`, `reports`, `project`, `provisioning` | `ret` / `code` / `msg` |
| `comments` | `ret` / `rtnCode` / `rtnDesc` |
| `pms` | `error` / `errorCode` / `errorMsg` |

Что в снимок не вошло:

- «Obtaining the Callback Result» (Publishing API) — это обратный вызов Huawei на адрес
  разработчика, а не операция API;
- «Obtaining a Project-Level Token» — тот же `POST /api/oauth2/v1/token`, что и обычное
  получение токена: в снимке одна операция `auth.token.create`;
- модели данных, приложения (языки, страны, категории, ограничения файлов, правила цен)
  и коды результата — отдельные страницы справочника; модели разобраны в
  `components/schemas`, остальное остаётся в справочнике.

Upload Management API описан в справочнике дважды. Снимок следует редакции каталога
References: она шире (в инициализации загрузки по частям есть `fileType` и `obbType`).

## Дополнение `overlay.toml`

Операции называются по `operationId` снимка, внешние операции — по ключу в
`x-agc-external-operations`. Тексты `description`, `reason` и `alternative` — для агента,
на английском.

| Раздел | Ключи | Смысл |
| --- | --- | --- |
| `[[groups]]` | `slug`, `title`, `reference` | Группы API в порядке вывода: название раздела справочника и его адрес. Группы снимка и дополнения должны совпадать. |
| `[[toolsets]]` | `slug`, `description`, `default`, `operations` | Наборы инструментов в порядке вывода. `default` — включён ли набор по умолчанию (без ключа — нет). Каждая операция входит ровно в один набор. |
| `[names]` | `"<operationId>" = "<имя>"` | Имя инструмента: «глагол_ресурс», snake_case, не длиннее 40 символов, уникальное. Задаётся для каждой операции, которая не исключена. |
| `[[access]]` | `level`, `reason`, `operations` | Исключения из уровня доступа. `level` — `read`, `write` или `destructive`; `reason` попадает в описание инструмента. |
| `[[exclude]]` | `operations`, `reason`, `alternative`, `callable` | Операции, которые не становятся инструментами. `reason` — почему, `alternative` — что вызвать вместо. `callable = false` запрещает вызов и через `api_request` (без ключа — `true`). |
| `[[deprecated]]` | `operation`, `replacement`, `note` | Замены для устаревших операций (сейчас раздела нет: устаревших операций в справочнике нет). Операция с `deprecated: true` в снимке исключается сама. |
| `[[secrets]]` | `kind`, `description`, `hint`, `operations`, `fields` | Поля ответов с секретами. `kind` — `credential` (учётные данные: агенту не отдаются), `download-url` (временная ссылка на файл) или `file-content` (содержимое файла с учётными данными); для двух последних у инструмента есть `save_to`, и у операции такое поле может быть только одного вида. `fields` — пути в JSON ответа через `.`, `[]` — каждый элемент массива; поле должно быть в схеме ответа `200` и быть строкой. `description` и `hint` попадают в пометку `note` агенту. |

Уровень доступа по умолчанию задаёт HTTP-метод: `GET` — чтение, `DELETE` — удаление,
остальное — запись. Исключения:

- удаление (`destructive`) — действия с последствиями для пользователей AppGallery и
  денег: отправка на проверку (обычная и в режиме скачивания), изменение поэтапного
  выпуска и времени выпуска, публичный ответ на отзыв, изменение товаров и цен,
  активация и деактивация товаров, создание, изменение, запуск и снятие акций, удаление
  сертификатов и устройств запросом `POST`;
- запись (`write`) — `GET`, который выдаёт адрес и заголовки для загрузки файла;
- чтение (`read`) — `POST`, который только читает: поиск товаров, акций, групп подписок,
  список сертификатов.

Изменение данных приложения, локализаций и файлов до отправки на проверку — запись.

Вне наборов могут быть только исключённые операции с `callable = false` (получение
токена). Ошибки, на которых должна падать сборка: операция без набора или в двух
наборах, операция без имени, повтор имени, имя длиннее 40 символов, ссылка на
несуществующую операцию или группу, исключение из уровня доступа, совпадающее с уровнем
по умолчанию, неизвестные ключи. Те же правила проверяет `test_spec.py`.

Внешние операции в таблицы операций не попадают: они должны быть исключены с
`callable = false` и не получают имени инструмента. `reason` исключения становится
пояснением исключённой операции, `alternative` — подсказкой, что вызвать вместо неё.

Шаги загрузки Upload Management API (получение адреса загрузки и загрузка по частям)
тоже исключены с `callable = false`, но остаются в наборе `releases`: их ответы целиком
состоят из одноразовых адресов и заголовков загрузки, а файл загружает составной
инструмент загрузки.

## Обновление

```sh
python3 -I crates/appgallery-connect-api/spec/update_spec.py --check        # только отчёт
python3 -I crates/appgallery-connect-api/spec/update_spec.py --draft DIR    # страницы и черновик
python3 -I crates/appgallery-connect-api/spec/update_spec.py --lock         # записать pages.lock.json
```

Скрипт (Python 3.10+, только стандартная библиотека) обращается только к порталу
документации Huawei, к самому AppGallery Connect API он не ходит. Запросы идут по одному,
с паузой; таймаут 45 с, до четырёх попыток при сбое сети, `408`, `429` и `5xx`. Страниц
около 155, полный проход занимает несколько минут.

- `--check` скачивает дерево и страницы, считает SHA-256 и сравнивает с
  `pages.lock.json`. Печатает изменённые, новые и пропавшие страницы, а также страницы,
  которые переименованы или перенесены в другой раздел без изменения текста. Ничего не
  записывает.
- `--draft DIR` сохраняет ответы портала в `DIR/pages/` и `DIR/tree.<каталог>.json` и
  пишет `DIR/draft.json` — черновик для ручной правки снимка:
  - `operations` — страницы с прототипом: метод, путь, параметры по расположению
    (`path`, `query`, `header`, `body`) с обязательностью, типом и описанием, вложенные
    таблицы моделей (`nestedTables`), поля ответа, примеры запроса и ответа, конверт
    результата (`result`, с пометкой `source`: из примера или из таблицы), режимы
    авторизации, адрес страницы и `notes` — расхождения, найденные при разборе (параметр
    есть в URL, но не в таблице; параметр в примере написан иначе; конверт не определён);
  - `external` — страницы с методом, но без адреса Connect API (отправка файла на адрес
    из ответа, обратный вызов);
  - `models` — страницы моделей данных с таблицей полей;
  - `other` — остальные страницы (обзоры, коды результата, приложения).
- `--lock` записывает `pages.lock.json` по текущим страницам.
- `--from-dir DIR` вместо сети читает дерево и страницы из каталога, заполненного
  `--draft`: так `--lock` и повторный `--draft` не скачивают страницы заново.
- `--lock-file FILE` — другой путь к списку страниц; `--quiet` — без хода загрузки.

Хеш считается по нормализованному тексту страницы: заголовки, абзацы, строки таблиц и
примеры кода без разметки. Идентификаторы элементов, классы, якоря и ширина колонок в
него не входят, поэтому перевёрстка страницы не считается изменением.

Коды выхода: `0` — расхождений нет или файл записан; `1` — `--check` нашёл расхождения;
`2` — портал недоступен (сеть, таймаут, ошибка портала после повторов, страница без
содержимого), не читается `pages.lock.json` или неверные аргументы.

Каталог с черновиком и скачанными страницами в репозиторий не добавляется.

Порядок работы, когда `--check` нашёл изменения:

1. `--draft DIR`, затем посмотри изменённые и новые страницы в `DIR/draft.json` и в
   справочнике;
2. поправь `openapi.json` вручную. Черновик — подспорье, а не источник истины:
   справочник местами неточен, и исправления по итогам живой сверки не должны затираться;
3. для новой операции добавь набор и имя в `overlay.toml`, проверь уровень доступа по
   правилам выше; для пропавшей — убери её из дополнения;
4. `--lock --from-dir DIR`;
5. запусти тесты и сборку крейта, просмотри изменения снапшотов операций.

Тесты (без сети):

```sh
python3 -I -B -m unittest discover -s crates/appgallery-connect-api/spec -p 'test_*.py'
```

`test_update_spec.py` проверяет разбор страниц, нормализацию и сравнение списков на
выдуманных фрагментах HTML. `test_spec.py` проверяет снимок и дополнение: у каждой
операции есть группа, конверт результата, набор и имя либо исключение; имена уникальны и
не длиннее 40 символов; все `$ref` разрешаются; пути начинаются с `/api/`; дополнение не
ссылается на несуществующие операции; страницы операций есть в `pages.lock.json`. Для
`test_spec.py` нужен Python 3.11+ (`tomllib`), на 3.10 он пропускается.

## Что проверить живой сверкой

Снимок собран только по справочнику, к API никто не обращался. Места, где справочник
противоречит сам себе или вызывает сомнения:

1. **Project Management API и режим API-клиента.** Все восемь операций группы `project`
   описаны только для режима OAuth-клиента (списки команд и приложений, отпечатки) или
   для OAuth-клиента и Service Account (проекты, сервисы, файл конфигурации). Работают ли
   они с токеном API-клиента — неизвестно (`x-agc-auth-modes`).
2. **Регистр `appId` в Comments API.** В таблицах параметров — `appId`, в примерах
   запросов списка отзывов и одного отзыва — `appid`. В снимке `appId`.
3. **`ratings` или `rating`.** У списка оценок в таблице параметр `ratings`, а в адресе
   прототипа — `rating`. В снимке `ratings`.
4. **Конверт без примера ответа.** У Reports API, Project Management API, получения
   адреса загрузки, инициализации и склейки загрузки по частям, списка пакетов и отправки
   пакета по ссылке нет примера ответа. Конверт `ret.code` / `ret.msg` взят из таблицы
   параметров, где `ret` местами назван строкой с JSON внутри. Нужно убедиться, что `ret`
   приходит объектом и что поля называются `code` и `msg`.
5. **Ошибка получения токена.** По таблице при ошибке приходит `ret` с кодом при HTTP 200;
   примера нет.
6. **Опечатка в путях.** `/api/cds/app-distirbution/v1/all/...` — так в справочнике (три
   операции группы `project`).
7. **Список сертификатов.** В таблице ответа поле называется `certInfo`, в примере —
   `certList`. В снимке оба.
8. **Список профилей.** `appId` и `provisionId` по справочнику передаются заголовками, хотя
   это `GET` со строкой запроса. В снимке — заголовки.
9. **Тело отправки на проверку.** У `publishing.app.submit` поля поэтапного выпуска лежат
   в корне тела и помечены обязательными, хотя нужны только при `releaseType=3`. В снимке
   тело необязательно, поля необязательны.
10. **Заголовки загрузки фрагмента.** У `FilePartUploadInfo.headers` в таблице тип — строка,
    в примере — объект. В снимке объект.
11. **Создание товаров и групп.** Отдельных операций создания товара и группы подписок в
    справочнике нет; по описаниям полей похоже, что их создают операции обновления
    (`pms.product.update`, `pms.product.batchUpdate`, `pms.productGroup.update`). От этого
    зависит и уровень доступа обновления группы (сейчас запись).
12. **Удаление локализации.** `publishing.languageInfo.delete` получает уровень удаления по
    методу `DELETE`. Если удаление меняет только черновик версии до отправки на проверку,
    уровень можно понизить до записи.
13. **`appID` и `appId`.** У `project.service.list` параметр называется `appID` и имеет
    целый тип, в ответе `project.appBriefInfo.list` поле — `appID`, в остальных местах —
    `appId` строкой.
14. **Отметки времени в Comments API.** Справочник описывает `beginTime` и `endTime` как
    миллисекунды «с 1970-01-01 08:00:00»; скорее всего это обычное время Unix.
15. **Ответы с секретами и временными ссылками.** `project.appExtraInfo.get` возвращает
    секрет приложения, `project.configFile.get` — файл конфигурации целиком, операции
    Reports API — временную ссылку на файл, операции сертификатов и профилей — временные
    ссылки на скачивание. Эти поля перечислены в `[[secrets]]` и скрываются по именам
    из снимка; при живой сверке нужно проверить, что настоящие ответы называют поля так же
    (`secret`, `content`, `fileURL`, `certDownloadUrl`, `provisionDownloadUrl`), что
    `content` — текст файла, а не ссылка, и что ссылки ведут на хосты Huawei.
16. **Две редакции Upload Management API.** В новой редакции (каталог `app`) у
    инициализации загрузки по частям нет `fileType` и `obbType`, а описание ограничено
    пакетами HarmonyOS. Нужно проверить, что параметры старой редакции принимаются.
