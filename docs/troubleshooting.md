# Решение проблем

Первым делом посмотрите, с чем запускается сервер и готов ли профиль:

```bash
appgallery-connect-mcp serve --status --profile <профиль>       # без сети: учётные данные, регион, уровень, наборы
appgallery-connect-mcp auth status --profile <профиль> --check  # учётные данные в хранилище и получение access token
```

`serve --status` не обращается к API. `auth status --check` получает access token и завершается ненулевым кодом, если профиль не готов.

## Homebrew не ставит формулу из стороннего tap

Устанавливайте по полному имени, а tap добавляйте с полным адресом: он размещён на SourceCraft, а не на GitHub.

```bash
brew tap filipov-dev/tap https://git.sourcecraft.dev/filipov-dev/homebrew-tap.git
brew install filipov-dev/tap/appgallery-connect-mcp
```

## Нет учётных данных

```
no API client credentials are stored for profile `…`; store them with `appgallery-connect-mcp auth login --profile …`
```

Для профиля из `serve --profile` в системном хранилище нет учётных данных; сервер с такой ошибкой не запускается (код выхода 1, сообщение в stderr). Проверьте имя профиля в конфигурации клиента (`appgallery` — профиль `default`, `agc-<профиль>` — остальные) и сохраните учётные данные:

```bash
appgallery-connect-mcp auth status
appgallery-connect-mcp auth login --profile <профиль>
```

Если в хранилище лежит повреждённое значение («is not a valid API client ID and secret»), тоже повторите `auth login`.


### Нет API-клиента проекта

```
this request is signed with a project-level API client, and no API client of project `…` is stored for this server: … Add one with `appgallery-connect-mcp auth project add --profile … --project-id …` …
```

Операции серверных API сервисов проекта подписываются API-клиентом проекта, а не команды. Скачайте файл клиента (проект → Project settings → Server SDK → API client → Download credential), сохраните его и перезапустите MCP-клиент:

```bash
appgallery-connect-mcp auth project add --profile <профиль> --credential-file <agc-apiclient-….json>
```

Сейчас это операции набора `remote-config` (Remote Configuration): `productId` в аргументах — Project ID проекта, для которого нужен клиент. Если сервер работает в HTTP-режиме, ошибка говорит об операторе сервера: клиент проекта добавляют на машине сервера в профиль `--profile`; сервер с `--secret-file` клиентов проекта не видит ([HTTP-режим](http.md)).

### Remote Configuration изменили одновременно

```
the Remote Configuration was changed by someone else after it was read at version … (result code 204083201, …). Nothing was written. …
```

Между чтением и записью `remote_config_set` конфигурацию изменили в консоли или другим вызовом. Ничего не записано: повторите `remote_config_set` с `dry_run: true`, покажите новую разницу пользователю и только потом записывайте. Та же защита — `baseVersion`: если текущая версия не та, которую видел пользователь, запись не делается.

## Учётные данные не приняты

```
could not get an access token in region … : AppGallery Connect rejected the API client credentials (HTTP …, code …): …
```

AppGallery Connect не выдал access token. Проверьте:

- Client ID и ключ скопированы целиком, без лишних символов (пробелы и переводы строк по краям сервер обрезает сам);
- API-клиент не удалён и его ключ не сбрасывали (Users and permissions → API key → Connect API);
- регион профиля совпадает с сайтом кабинета ([Регион не тот](#регион-не-тот)).

Если ключа больше нет, создайте новый API-клиент ([API-клиент](api-client.md#создание-api-клиента)) и сохраните его: `appgallery-connect-mcp auth login --profile <профиль>`. Если запрос токена не дошёл до AppGallery Connect («could not reach the AppGallery Connect token endpoint»), это сеть: проверьте подключение и прокси.

## Ошибки Huawei с HTTP 200

AppGallery Connect сообщает о многих ошибках не кодом HTTP, а ненулевым кодом в теле ответа с HTTP 200. Сервер проверяет конверт результата операции и возвращает такой ответ как ошибку инструмента:

```
AppGallery Connect API returned an error for `get_app_info`: code 204144641: Invalid input parameter (HTTP 200, ret.code). The request did not succeed even though the HTTP status is 200 …
```

В скобках — HTTP-статус и поле, где пришёл код. Конверты разные:

| Группы API | Поле кода | Поле текста |
| --- | --- | --- |
| Publishing, Upload, Reports, Project, Provisioning | `ret.code` | `ret.msg` |
| Comments (отзывы) | `ret.rtnCode` | `ret.rtnDesc` |
| PMS (товары и подписки) | `error.errorCode` | `error.errorMsg` |

Успешный результат инструмента значит, что код был `0`. У `api_request` конверт определяется по пути, а для неизвестного пути — по телу ответа.

## Частые коды результата

Коды — из страниц Result Codes справочника Huawei. Полные списки: [Publishing API](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-publishingapi-errorcode-0000001163523297), [Comments API](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-comment-returncode-0000001116028252), [PMS API](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-pms-returncode-0000001115868366), [Reports API](https://developer.huawei.com/consumer/en/doc/development/AppGallery-connect-References/agcapi-reportsapi-errorcode-0000001165183667).

Publishing API (`ret.code`):

| Код | Что значит | Что делать |
| --- | --- | --- |
| `204144641`, `204144654` | Неверный параметр. | Сверьте аргументы со схемой инструмента (`api_search` с `tool_name`). |
| `204144644` | Не удалось получить сведения о приложении. | Проверьте `appId`, что приложение в этом кабинете и регион профиля. |
| `204144650`, `204144653` | Языка, для которого меняются сведения, нет у приложения. | Сначала добавьте язык (`listing_apply` добавляет его по `title.txt`). |
| `204144651` | Язык по умолчанию удалить нельзя. | Смените язык по умолчанию или не удаляйте его. |
| `204144660` | Сбой при отправке на проверку; в тексте — код причины, например `80210116` (AAB больше 150 МБ) или `80210105` (AAB не разбирается bundletool). | Исправьте пакет и загрузите заново. |
| `204144664` | Не прошла проверка перед отправкой на проверку. | Посмотрите `release_status` и текст ошибки. |
| `204144666` | Пользователь заблокирован или его личность не подтверждена. | Проверьте статус аккаунта в AppGallery Connect. |
| `204144727` | Пакет ещё собирается. | Повторите через 3–5 минут; `release_submit` с `waitSeconds` ждёт сам. |
| `204144756` | Приложения не существует. | Проверьте `appId` и регион профиля. |

Comments API (`ret.rtnCode`):

| Код | Что значит |
| --- | --- |
| `50010003` | Неверный параметр запроса. |
| `50010034` | Между началом и концом периода больше шести месяцев (`reviews_summary` режет период сам). |
| `50010027`, `50010028` | Приложения нет или оно не ваше: проверьте `appId` и регион. |
| `50010040` | Неверный код страны или региона. |
| `50010077` | Разработчик уже ответил на этот отзыв. |

PMS API (`error.errorCode`): `301` — нет прав на операцию, `400` и `600` — неверный параметр, `20009` — товара нет, `20001` и `3000008` — товар уже существует. Reports API (`ret.code`): `204275713` — неверный параметр, `204275716` — данных больше, чем помещается в Excel (сократите период или выберите CSV).

## Нет прав: HTTP 403 и коды прав

```
AppGallery Connect API returned HTTP 403 Forbidden for `…`: … The API client is not allowed to do this …
```

Проверьте по порядку:

1. **Роли API-клиента.** Users and permissions → API key → Connect API: у клиента должна быть роль с нужным правом ([Роли](api-client.md#роли)). Проще всего — Administrator.
2. **Поле Project.** API-клиент, созданный с выбранным проектом, получает 403 на вызовы API. Для `auth login` создайте клиент с Project = N/A. API-клиент проекта (Server SDK) сохраняется отдельно — `auth project add` ([API-клиент проекта](api-client.md#api-клиент-проекта)).
3. **Кабинет.** Приложение должно принадлежать кабинету этого API-клиента.
4. **Регион** профиля совпадает с сайтом кабинета ([ниже](#регион-не-тот)).

Иногда отказ по правам приходит не статусом 403, а кодом в теле при HTTP 200 (например, `301` у PMS API): действуйте так же. Повторять запрос без изменений бесполезно.

## 403 у Project Management API

Справочник Huawei описывает операции набора `projects` (команды, проекты, сервисы, файл конфигурации, отпечатки сертификатов) только для OAuth-клиента и Service Account. С API-клиентом они могут отвечать отказом по правам даже при роли Administrator ([Project Management API](api-client.md#project-management-api)).

- `search_apps` в этом случае сам переходит на поиск через Publishing API: передайте имена пакетов (`packageNames`) или сохраните их в профиле (`--default-package`).
- `config_download` советует скачать `agconnect-services.json` в AppGallery Connect вручную: Project settings → General information.
- Остальные наборы этим не затронуты.

С [входом пользователя](api-client.md#вход-пользователя-oauth-клиент) эти операции работают, если HUAWEI ID выдал OAuth-клиенту область `project` (`auth status` показывает выданные области) и у пользователя в команде есть роль с доступом к проектам.

## Вход пользователя

- **Браузер вернулся со страницей «No authorization code», а команда ждёт.** HUAWEI ID отказал во входе и сообщил причину во фрагменте адреса (`#error=…`), который команда не видит. Посмотрите адрес в строке браузера. Частые причины: адрес возврата не совпадает с адресом OAuth-клиента (тогда передайте `--redirect-uri` с адресом из настроек приложения), области ещё не одобрены, вход отменён. Можно прервать команду Ctrl-C или дождаться таймаута (5 минут).
- **`sub_error 12304` или `20172`** — неверный секрет OAuth-клиента. **`12303`, `20002`** — неверный client ID. **`20022`–`20024`, `22023`** — адрес возврата не совпадает (`--redirect-uri`). **`20152`–`20156`** — код входа устарел или уже использован: войдите заново.
- **`sub_error 11205`, `31204`, `31202`, `31218`, `20192`** при работе сервера или `auth status --check`: refresh token истёк (180 дней) или отозван, например после смены пароля HUAWEI ID или снятия доступа в Privacy center → Control account access. Войдите снова: `auth login --oauth --profile <профиль>`.
- **Список команд не получен.** Чаще всего OAuth-клиенту не выдана область `project`. Передайте `--team-id` (ID команды есть в AppGallery Connect → Users and permissions) или запросите область у Huawei.
- **«is not available when the server works as a signed-in user».** Операцию (например, Comments API: отзывы и ответы на них) справочник описывает только для API-клиента. Запрос не отправлялся. Для неё нужен отдельный профиль с API-клиентом.
- **«signed-in user is not a member of team».** Пользователя удалили из команды, или профиль сохранён с другой командой. Войдите снова и выберите команду.
- **HTTP-сервер со входом пользователя.** Ошибки входа агент передаёт оператору сервера: войдите заново на машине сервера (`auth login --oauth --profile <профиль> --no-browser`) и перезапустите `serve --http`. `--region` у такого сервера должен совпадать с сайтом команды или не задаваться.
- **`key exec` отказывает.** У профиля со входом пользователя нет API-клиента команды, а refresh token другим программам не отдаётся. Для Gradle-плагина и fastlane нужен профиль с API-клиентом.

## Регион не тот

У AppGallery Connect API несколько сайтов (`cn`, `de`, `sg`, `ru`), и кабинет живёт на одном из них. Признаки неверного региона: приложение «не существует» (`204144756`, `50010027`), HTTP 404, пустой список приложений, отказ в выдаче токена.

```bash
appgallery-connect-mcp auth status --profile <профиль>                 # строка Region
appgallery-connect-mcp auth login --profile <профиль> --region ru      # сменить регион
```

`auth login` с новым регионом заново спрашивает Client ID и секрет (или возьмите `--secret-file`). Отзывы и оценки тоже привязаны к сайту: страны в одном запросе (`countries`) должны обслуживаться одним сайтом.

## Ключ отклонён: HTTP 401

Сервер сам один раз повторяет запрос с новым токеном. У входа пользователя повторный 401 значит, что вход отозван или у пользователя больше нет доступа к команде: войдите снова (`auth login --oauth`). Если 401 повторяется у API-клиента, он удалён или его ключ сброшен: проверьте `auth status --check` и сохраните новые учётные данные через `auth login`. Не вставляйте ключ в чат с агентом.

## Квоты, HTTP 429 и 5xx

Сервер сам повторяет запросы после `429`, `500`, `502`, `503` и `504` с растущей паузой (с учётом `Retry-After`): до трёх раз и не дольше 30 секунд паузы. Повторяются только идемпотентные запросы (`GET`, `PUT`, `DELETE`); `POST` и `PATCH` не повторяются, чтобы не выполнить действие дважды. Если ошибка осталась, проверьте, выполнилось ли действие (например, `release_status`), прежде чем повторять.

## Загрузка пакета

- `package_upload` проверяет тип и размер файла до запросов: APK, APP, EXE — до 4 ГБ, AAB — до 150 МБ, RPK — до 30 МБ.
- `packageStatus: "processing"` — AppGallery Connect ещё обрабатывает пакет (AAB собирается в APK). Подождите и проверьте `release_status` или вызовите `release_submit` с `waitSeconds`.
- `packageStatus: "failed"` — сборка не удалась, причина в ответе. Исправьте пакет и загрузите заново.
- Для кабинетов, зарегистрированных вне материкового Китая, AppGallery Connect требует указать, распространяется ли пакет в Китае: аргумент `chineseMainland`.

## Агенту не хватает инструмента

Вызов незарегистрированного инструмента по имени возвращает ошибку с причиной:

- инструмент выше уровня доступа сервера — перезапустите его с `--allow-write` или `--allow-destructive`, например повторным `connect … --allow-write`;
- набор не включён — с динамическими наборами агент включает его сам через `enable_toolset`; без них добавьте набор в `--toolsets` (или `--toolsets all`). Операцию в пределах уровня доступа можно вызвать и через `api_request`;
- операции нет среди инструментов (получение токена, шаги загрузки) — `api_search` найдёт её и скажет, чем её заменить;
- с динамическими наборами клиент не показывает новые инструменты после `enable_toolset`: не все клиенты перечитывают список по `notifications/tools/list_changed`. Агент может вызывать те же операции через `api_request`, или подключите сервер без динамических наборов (`connect … --no-dynamic-toolsets`).

Какие наборы и сколько инструментов включено, показывает `serve --status`; все наборы — `appgallery-connect-mcp toolsets`; конкретный список — `tools list` с флагами сервера.

## Ответ слишком большой

Результат больше `--max-response-bytes` (256 КиБ по умолчанию) возвращается ошибкой с подсказкой сузить запрос:

- уменьшите страницу и уточните фильтры, сократите период;
- запрашивайте один язык (`lang`) вместо всех;
- выберите нужное фильтром `jq` — лимит действует на результат фильтра;
- отчёты сохраняйте в файл: `report_download` с `save_to`.

Лимит можно увеличить флагом `--max-response-bytes` в аргументах сервера.

## Файл «is outside the allowed directories» или «already exists»

Инструменты работают с локальными файлами только в рабочем каталоге сервера, системном временном каталоге и каталогах из `--allow-path`. Если клиент запускает сервер в домашнем каталоге или в `/`, рабочий каталог не разрешён. Добавьте нужный каталог: `appgallery-connect-mcp connect … --allow-path /path/to/project` или `--allow-path` в аргументах сервера ([Безопасность](security.md#локальные-файлы)).

Сохранение никогда не перезаписывает существующий файл: укажите новое имя в `save_to` (или новый пустой каталог в `dir` для `listing_export`).

## Linux: Secret Service недоступен

В Linux учётные данные хранятся через Secret Service (D-Bus). Ошибка

```
the system keychain is not available: no Secret Service (org.freedesktop.secrets) is available on the D-Bus session bus …
```

при `connect`, `auth` или `serve` означает одно из:

- в сессии не запущен провайдер Secret Service — GNOME Keyring, KeePassXC (с включённой интеграцией Secret Service), KDE Wallet и т. п.;
- нет сессионной шины D-Bus: например, при входе по SSH на сервер без графической сессии;
- связка ключей заблокирована и разблокировать её некому.

Запасного файлового хранилища нет, и хранить секрет в переменной окружения нельзя — это намеренное ограничение. На машине без графической сессии можно поднять шину и разблокированное хранилище вручную (пример для Debian/Ubuntu):

```bash
sudo apt-get install dbus-daemon gnome-keyring libsecret-tools
dbus-run-session -- sh
# внутри новой оболочки: введите пароль связки ключей и нажмите Ctrl-D
gnome-keyring-daemon --unlock --components=secrets
appgallery-connect-mcp auth login --client-id <Client ID> --secret-file agc-secret.txt
appgallery-connect-mcp auth status
```

Хранилище живёт, пока жива эта сессия D-Bus: MCP-клиент, который запускает `appgallery-connect-mcp serve`, должен работать внутри неё.

## Linux: ошибка проверки сертификата

Сертификаты API Huawei проверяются по корневым сертификатам системы. Если запросы падают с ошибкой TLS или сертификата, поставьте пакет `ca-certificates` (в минимальных образах его нет).

## macOS: Keychain спрашивает разрешение

macOS может спросить, разрешить ли `appgallery-connect-mcp` доступ к записи `dev.filipov.appgallery-connect-mcp` в связке ключей — обычно когда учётные данные сохранила одна сборка бинарника, а читает другая. Нажмите «Всегда разрешать», иначе вопрос будет повторяться при каждом запуске сервера.

Бинарник из Homebrew и релизных архивов подписан Developer ID, поэтому после обновления разрешение, как правило, сохраняется. Бинарник, собранный из исходников, не подписан: после пересборки macOS может спросить снова. Когда сервер запускает MCP-клиент, окно с вопросом появляется поверх других окон, а клиент ждёт ответа.

## Windows: Credential Manager недоступен

В Windows Credential Manager есть только в сеансе, вошедшем с паролем: в SSH-сеансе со входом по ключу, в службе или задаче планировщика без сохранённого пароля `auth`, `connect` и `serve` падают с ошибкой хранилища (например, «A specified logon session does not exist»). Выполните `connect` и запускайте MCP-клиент в обычном сеансе пользователя ([Windows](clients.md#windows)).

## Windows: SmartScreen не даёт запустить бинарник

Бинарник для Windows не подписан сертификатом подписи кода. Если SmartScreen показывает «Система Windows защитила ваш компьютер», проверьте контрольную сумму архива по `SHA256SUMS` и нажмите «Подробнее» → «Выполнить в любом случае»; чтобы предупреждение не появлялось, перед распаковкой выполните `Unblock-File` для архива ([Установка: Windows](install.md#windows)). Smart App Control в Windows 11 блокирует неподписанные программы без возможности запуска.

## Windows: файл занят при обновлении

Пока MCP-клиент держит сервер запущенным, `appgallery-connect-mcp.exe` заменить нельзя. Закройте клиент или переименуйте старый файл и удалите его после перезапуска клиента ([Установка: Windows](install.md#windows)).

## Клиент не видит сервер или его инструменты

- Перезапустите клиент после `connect` или правки конфигурации.
- Укажите в конфигурации клиента абсолютный путь к бинарнику (`command -v appgallery-connect-mcp`).
- Запустите команду из конфигурации вручную, например `appgallery-connect-mcp serve --profile default`. Ошибки запуска (нет учётных данных, недоступно хранилище, неизвестный набор, несуществующий каталог в `--allow-path`, ошибка в `tools.toml`) печатаются в stderr, в stdout при этом ничего нет. Если ошибок нет, сервер ждёт сообщений MCP на stdin — остановите его `Ctrl-C`.
- Для подробных логов добавьте в аргументы сервера `--log-level debug`. Логи пишутся только в stderr, секрет и токен в них не попадают.
- Имя сервера длиннее 17 символов `connect` не принимает; при ручной регистрации клиент может укоротить или отклонить часть инструментов ([Имя сервера](clients.md#имя-сервера)).

## Покупки в приложении: нет секрета или ошибка IAP

- «no app secret of app … is stored»: у профиля нет секрета этого приложения. Сохраните его командой `appgallery-connect-mcp auth app-secret set --profile <профиль> --app <App ID>` и перезапустите MCP-клиент ([Секрет приложения](api-client.md#секрет-приложения)). В HTTP-режиме секрет сохраняет оператор сервера.
- «could not get an app-level access token»: Huawei OAuth отклонил client ID или секрет приложения. Проверьте их в AppGallery Connect (My apps → приложение → App information) и сохраните заново.
- Ошибка с `responseCode` и HTTP 200 — ответ сервиса IAP: `5` — In-App Purchases не включён у приложения, `6` — сбой на стороне Huawei (повторите позже), `8` — пользователь не владеет товаром, `9` — покупка уже подтверждена, `11` — проблема с учётной записью пользователя, `12` — заказа нет или токен покупки не последний. Проверить можно только последний токен товара: после подтверждения и повторной покупки старый токен даёт `12`.
- `list_cancelled_purchases` отвечает только за последние 30 дней, `list_iap_orders` — за период не длиннее 48 часов.
