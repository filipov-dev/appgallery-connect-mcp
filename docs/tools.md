# MCP-инструменты

Каждая операция AppGallery Connect API из встроенного снимка спецификации — отдельный MCP-инструмент: Publishing API, Upload Management API, Reports API, Comments API, PMS API (товары и подписки), Project Management API и Provisioning API (подпись HarmonyOS). Снимок ведётся по страницам справочника Huawei, потому что машинной спецификации у Huawei нет. Поверх операций есть двенадцать [составных инструментов](#составные-инструменты), которые выполняют многошаговые сценарии за один вызов. Всегда доступны `api_search` и `api_request`.

Какие инструменты видит агент, задают уровень доступа (`--allow-write`, `--allow-destructive`) и наборы (`--toolsets`) сервера:

| Наборы | Чтение | Запись | Удаление |
| --- | ---: | ---: | ---: |
| по умолчанию (`apps`, `releases`, `reviews`) | 14 | 18 | 25 |
| все (`--toolsets all`) | 37 | 51 | 70 |

Числа включают `api_search` и `api_request` и соответствуют выводу `appgallery-connect-mcp tools list` этой версии. С динамическими наборами (по умолчанию после `connect`) при запуске их пять. Посмотреть список для своих настроек: `appgallery-connect-mcp tools list` с теми же флагами или `appgallery-connect-mcp serve --status`.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с флагом, который их включает.

| Уровень | Как включить | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение |
| write | `--allow-write` | плюс создание и изменение (`POST`, `PUT`, `PATCH`) |
| destructive | `--allow-destructive` (включает запись) | плюс удаление (`DELETE`) и действия с последствиями для пользователей AppGallery и денег |

Уровень операции по умолчанию — по методу: `GET` — чтение, `DELETE` — удаление, остальное — запись. Исключения заданы в файле-дополнении спецификации, а причина попадает в описание инструмента («Destructive: …»), поэтому агент её видит.

Уровень удаления, кроме `DELETE`, получают действия, последствия которых видят пользователи или которые затрагивают деньги:

| Действие | Инструменты |
| --- | --- |
| Отправка версии на проверку; после одобрения она выходит к пользователям | `submit_app`, `submit_app_with_file`, `release_submit` |
| Поэтапный выпуск: доля пользователей, пауза, выпуск для всех | `update_phased_release`, `release_manage` |
| Время выпуска одобренной версии, вплоть до выпуска сразу | `update_release_time`, `release_manage` |
| Публичный ответ на отзыв | `reply_review` |
| Товары и их цены | `update_product`, `batch_update_products` |
| Товары в продаже и снятие с продажи | `activate_products`, `deactivate_products` |
| Акции: создание, изменение, запуск и снятие | `create_promotion`, `update_promotion`, `release_promotions`, `remove_promotions` |
| Удаление сертификатов и устройств (запросом `POST`) | `delete_certificates`, `delete_devices` |
| Удаление локализации и профиля подписи (`DELETE`) | `delete_app_language_info`, `delete_profile` |

Изменения до отправки на проверку — уровень записи: загрузка пакета, сведения о приложении, локализации, изображения. Пользователи видят их только после того, как версия отправлена и одобрена.

Исключения в обратную сторону:

- получение адреса загрузки файла (`GET`) — уровень записи: ответ выдаёт одноразовые учётные данные для загрузки;
- `POST`-методы, которые только читают, — уровень чтения: `list_product_groups`, `search_products`, `search_promotions`, `list_certificates`.

У каждого инструмента есть аннотации MCP `readOnlyHint` и `destructiveHint` по его уровню. Флаги командной строки важнее настроек профиля ([`serve`](cli.md#serve)). Уровень доступа сервера не расширяет роли API-клиента: AppGallery Connect всё равно проверяет их ([Роли](api-client.md#роли)).

### Динамические наборы

Клиенты, которые не откладывают загрузку инструментов, кладут описания всех зарегистрированных инструментов в контекст модели сразу. С `serve --dynamic-toolsets` (или `dynamic_toolsets = true` в профиле; `connect` включает это по умолчанию) сервер при запуске регистрирует только:

- `api_search` и `api_request`;
- `list_toolsets` — наборы с описанием, числом инструментов на уровне доступа сервера, примерами имён и признаком, включён ли набор;
- `enable_toolset` — включить набор (аргумент `toolset`, можно несколько через запятую);
- `disable_toolset` — выключить набор;
- наборы из `--toolsets` или профиля (без них — ни одного).

После `enable_toolset` и `disable_toolset` сервер отправляет клиенту `notifications/tools/list_changed`. Уровень доступа действует как обычно: включение набора не регистрирует инструменты выше него. Если клиент не перечитывает список инструментов, агент может вызвать ту же операцию через `api_request`.

## Приложения и аргументы

- Приложение адресуется числовым App ID (`appId`, например `100000001`), а не именем пакета. App ID по имени пакета отдаёт `list_app_ids`, список приложений кабинета — `search_apps`. Приложения по умолчанию можно сохранить в профиле ([Приложения по умолчанию](api-client.md#приложения-по-умолчанию)).
- Параметры пути, запроса и заголовков — обычные аргументы с именами, как в справочнике Huawei: `appId`, `lang`, `releaseType`. Часть параметров Huawei передаётся заголовками (например `appId` у PMS API): для агента это тоже обычный аргумент.
- Тело запроса — аргумент `body` (JSON-объект).
- Неизвестные аргументы отклоняются, обязательные аргументы и типы параметров проверяются до запроса. Внутри `body` проверяются только типы известных полей: справочник Huawei местами неточен в обязательных полях, решает AppGallery Connect.
- Повторяющиеся параметры запроса (`filterCondition` и `filterConditionValue` у отчётов) передаются JSON-массивом и уходят повтором `?a=1&a=2`. Списки, которые справочник описывает строкой через запятую (`countries` у `list_reviews`), передаются строкой.
- Описание каждого инструмента операции заканчивается ссылкой на его страницу в справочнике Huawei.

## Ответы и ошибки

Ответ — JSON-ответ AppGallery Connect API как есть, вместе с конвертом результата (`ret`, `error`). Единой постраничной выдачи у API нет: у разных групп свои параметры (например, `page` и `limit` у отзывов, `fromPage` и `pageSize` у проектов), они передаются обычными аргументами.

AppGallery Connect сообщает о многих ошибках с HTTP 200 и ненулевым кодом в теле ответа. Конверт у групп API разный:

| Группы API | Поле кода | Поле текста |
| --- | --- | --- |
| Publishing, Upload, Reports, Project, Provisioning | `ret.code` | `ret.msg` |
| Comments | `ret.rtnCode` | `ret.rtnDesc` |
| PMS | `error.errorCode` | `error.errorMsg` |

Сервер проверяет код и возвращает такой ответ как ошибку инструмента (`isError: true`) с кодом и текстом Huawei. Успешный результат значит, что код был `0`. Ошибки HTTP (`4xx`, `5xx`) тоже возвращаются результатом с `isError: true`: статус, код и текст Huawei и подсказка, что делать ([Решение проблем](troubleshooting.md#ошибки-huawei-с-http-200)).

Результат больше `--max-response-bytes` (256 КиБ по умолчанию) — ошибка с подсказкой сузить запрос: меньше страница, строже фильтры, меньше языков или фильтр `jq`.

## Файлы и save_to

Некоторые ответы почти целиком состоят из секрета или временной ссылки. Сервер скрывает такие поля (`***`), а у инструмента появляется аргумент `save_to` — путь нового локального файла. С `save_to` сервер сам скачивает файл по ссылке (только с хостов Huawei) или записывает содержимое и возвращает агенту путь, размер, имя поля и тип: `saved: {path, bytes, field, content_type}`. Ссылка и содержимое в ответ не попадают.

| Инструмент | Что сохраняет |
| --- | --- |
| `get_download_report_url`, `get_iap_report_url`, `get_paid_app_report_url`, `get_paid_app_details_report_url`, `get_install_failure_report_url` | Файл отчёта по временной ссылке `fileURL`. |
| `get_app_config_file` | Файл конфигурации `agconnect-services.json` (поле `content`). |
| `create_certificate`, `list_certificates` | Файл сертификата по временной ссылке; у списка — один файл, сузьте список до одного сертификата. |
| `create_profile`, `update_profile_devices`, `list_profiles` | Файл профиля подписи по временной ссылке; у списка — один файл. |

Секрет приложения (`get_app_fingerprints`, поле `secret`) сервер не отдаёт никак: ни в ответе, ни в файл.

Составные инструменты, которые работают с файлами:

- `report_download` и `config_download` — сохраняют в `save_to`;
- `listing_export` — пишет каталог страницы приложения (`dir`);
- `image_sync` — читает каталог и обновляет в нём файл `.appgallery-images.json`;
- `package_upload` и `listing_apply` — только читают (`file`, `dir`).

Пути работают только в [разрешённых каталогах](security.md#локальные-файлы), существующие файлы не перезаписываются (кроме `.appgallery-images.json`, который `image_sync` заменяет новым). Путь проверяется до запроса к API. `save_to` и `jq` в одном вызове не сочетаются.

Шаги загрузки Upload Management API (адрес загрузки, загрузка по частям) не стали инструментами и не вызываются через `api_request`: их ответы — одноразовые адреса и заголовки загрузки. Пакеты загружает `package_upload`, изображения и видео — `image_sync`.

## api_search и api_request

- `api_search` ищет по всем операциям API без обращения к нему: инструменты операций (включая невключённые наборы и инструменты выше уровня доступа), исключённые операции и составные инструменты. Слова — на английском или русском: русские термины переводятся словарём («отзыв» → review, «подписка» → subscription, «выпуск» → release и т. д.), английские сравниваются по началу слова. Каждый результат говорит, в каком наборе инструмент, какого он уровня, можно ли вызвать его на этом сервере и что его включает (флаг доступа, набор, вызов через `api_request`). Аргументы: `query`, `toolset`, `limit` (по умолчанию 15, до 50); с `tool_name` — полное описание и схема одного инструмента.
- `api_request` вызывает любой путь AppGallery Connect API на хосте региона профиля в пределах уровня доступа сервера (наборы его не ограничивают): `method` (`GET` по умолчанию, `POST`, `PUT`, `PATCH`, `DELETE`), `path` от корня хоста, начинается с `/api/` (query можно после `?`), `query`, `headers` (заголовочные параметры, например `appId` у PMS API), `body`. Уровень берётся у операции, которой соответствует путь; для неизвестного пути — по методу. Полные адреса, `..`, `//`, заголовки `Authorization` и `client_id` и параметры с именами учётных данных отклоняются. Получение токена и шаги загрузки через `api_request` недоступны. Ошибки с HTTP 200 определяются так же, как у инструментов операций; секретные поля совпавшей операции скрываются. `save_to` у `api_request` нет.

Примеры: названия приложения по языкам и товар PMS API (`appId` у PMS API — заголовок), если наборы выключены:

```json
{"path": "/api/publish/v2/app-info", "query": {"appId": "100000001"}, "jq": "[.languages[] | {lang, appName}]"}
```

```json
{"path": "/api/pms/product-price-service/v1/manage/product", "query": {"productNo": "premium_month"}, "headers": {"appId": "100000001"}}
```

Сверьте имена параметров со схемой инструмента (`api_search` с `tool_name`): `api_request` их не проверяет.

## Фильтр jq

Инструменты операций с JSON-ответом, составные и пользовательские инструменты и `api_request` принимают необязательный аргумент `jq` — фильтр в диалекте [jaq](https://github.com/01mf02/jaq), например `[.languages[] | {lang, appName}]` для `get_app_info` или `[.appids[] | .value]` для `list_app_ids`.

- Фильтр применяется к телу ответа (вместе с конвертом результата) после вырезания секретов. Если что-то вырезано, пометка остаётся снаружи: `{"result": <результат фильтра>, "note": ...}`. Лимит `--max-response-bytes` действует на результат фильтра. Несколько результатов возвращаются массивом, ни одного — `[]`.
- Синтаксис проверяется до запроса к API. Ошибка выполнения фильтра после изменяющего запроса прямо говорит, что запрос выполнен и повторять его не нужно.
- Фильтру недоступны окружение, файлы и `input`. Сервер выполняет фильтры в дочернем процессе того же бинарника (скрытая команда `jq-worker`) с пустым окружением и таймаутом 10 секунд: зацикливание или переполнение стека завершают только этот процесс.

## Составные инструменты

Составной инструмент делает несколько запросов к API за один вызов. Ответ проходит ту же обработку, что и ответы операций (вырезание секретов, `jq`, лимит размера), и собирается из выбранных полей: адресов загрузки, временных ссылок и содержимого файлов с учётными данными в нём нет. `appId` у всех, где он есть, необязателен, если в профиле ровно одно приложение по умолчанию.

| Инструмент | Набор | Уровень | Что делает |
| --- | --- | --- | --- |
| [`search_apps`](#search_apps) | `apps` | чтение | Приложения кабинета с App ID, пакетами и проектами; поиск по пакету и названию. |
| [`app_overview`](#app_overview) | `apps` | чтение | Краткая сводка по приложению: версия, выпуск, рейтинг. |
| [`config_download`](#config_download) | `apps` | чтение | `agconnect-services.json` — в файл, без содержимого в ответе. |
| [`release_status`](#release_status) | `releases` | чтение | Состояние версии, проверки, выпуска и пакетов. |
| [`package_upload`](#package_upload) | `releases` | запись | Загрузка APK, AAB, RPK, APP или EXE и привязка к приложению. |
| [`release_submit`](#release_submit) | `releases` | удаление | Отправка версии на проверку: сразу, по времени или поэтапно. |
| [`release_manage`](#release_manage) | `releases` | удаление | Поэтапный выпуск и время выпуска. |
| [`listing_export`](#listing_export-listing_apply-и-image_sync) | `listing` | чтение | Страница приложения — в локальный каталог. |
| [`listing_apply`](#listing_export-listing_apply-и-image_sync) | `listing` | запись (удаление языков — удаление) | Тексты из каталога — в AppGallery Connect, с просмотром разницы. |
| [`image_sync`](#listing_export-listing_apply-и-image_sync) | `listing` | запись | Иконка, скриншоты и видео из каталога. |
| [`reviews_summary`](#reviews_summary) | `reviews` | чтение | Сводка отзывов за любой период. |
| [`report_download`](#report_download) | `reports` | чтение | Отчёт — в файл или краткой сводкой. |

Аргументы ниже — в том виде, в каком их передаёт агент; обычно он сам подбирает их по просьбе пользователя. Полная схема — `api_search` с `tool_name`.

### search_apps

Список приложений кабинета с App ID, именами пакетов, названиями и проектами. Приложения профиля идут первыми (`default: true`). Список берётся из Project Management API (проекты и их приложения). Если этот API отказывает API-клиенту, инструмент ищет App ID для пакетов из `packageNames`, профиля и `query` (если он похож на имя пакета) через `list_app_ids`: тогда `source: "publishing"`, `projectsAvailable: false`, и находятся только приложения с известным именем пакета.

Аргументы: `query` (часть имени пакета или названия, без учёта регистра), `packageNames` (точные имена пакетов), `limit` (до 500, по умолчанию 50).

```json
{"query": "example"}
```

### app_overview

Краткая сводка по одному приложению: название на языке по умолчанию, коды языков, категории, платное или нет, число стран выпуска, возрастной рейтинг, версия в подготовке или на проверке с её состоянием, выпущенная версия, последний отзыв проверки, поэтапный выпуск и средняя оценка пользователей за 180 дней. Описаний, изображений и цен нет. Что не удалось прочитать (например, оценку), объясняют `notes`.

Аргументы: `appId`, `countries` (страны для оценки, одного сайта AppGallery Connect; по умолчанию `RU` для профиля региона `ru` или единственная страна выпуска).

```json
{"appId": "100000001", "countries": ["RU"]}
```

### config_download

Сохраняет файл конфигурации приложения `agconnect-services.json` в новый локальный файл. В файле учётные данные приложения, поэтому его содержимое агенту не отдаётся: в ответе путь, размер и имена ключей верхнего уровня без значений (`topLevelKeys`). Работает через Project Management API: при отказе по правам инструмент советует скачать файл в AppGallery Connect (Project settings → General information).

Аргументы: `save_to` (обязателен), `appId`.

```json
{"appId": "100000001", "save_to": "app/agconnect-services.json"}
```

### release_status

Состояние выпуска за один вызов: версия в подготовке или на проверке (название и код версии, состояние проверки и выпуска, последний отзыв проверки), выпущенная версия, ждёт ли одобренная версия запланированного выпуска, поэтапный выпуск (состояние, доля, начало и конец), последние пакеты и состояние сборки пакета текущей версии (`readyToSubmit`). Времени запланированного выпуска API не отдаёт.

Аргументы: `appId`, `maxPackages` (0–20, по умолчанию 5).

### package_upload

Загружает пакет и привязывает его к приложению. `file` — локальный APK, AAB, RPK, APP (HarmonyOS) или EXE (Windows). До запросов инструмент проверяет тип и размер (APK, APP, EXE — до 4 ГБ, AAB — до 150 МБ, RPK — до 30 МБ). Файл больше 100 МБ загружается частями с повторами. AAB по умолчанию ждёт, пока AppGallery Connect его обработает. На проверку инструмент не отправляет: это отдельный шаг (`release_submit`).

Ответ: имя, размер, тип и SHA-256 файла, `pkgId`, `packageStatus` (`ready`, `processing`, `failed`, `not_checked`, `unknown`), `readyForReview`, число частей и повторов.

Аргументы: `file` (обязателен), `appId`, `waitSeconds` (0–1800; по умолчанию 300 для AAB и 0 для остальных), `chineseMainland` (распространяется ли пакет в материковом Китае, по умолчанию `false`), `releaseType` (1 — полный выпуск, 3 — поэтапный), `versionName` и `displayName` (только и обязательно для EXE), `dryRun` (только проверить и описать загрузку).

```json
{"appId": "100000001", "file": "build/app-release.aab"}
```

### release_submit

Отправляет версию в подготовке на проверку и выпуск. Результат видят пользователи AppGallery: после одобрения версия выходит к ним, а отозвать отправку через API нельзя. Агент вызывает инструмент только по явной просьбе пользователя и сначала с `dryRun: true`. До отправки инструмент проверяет, что версия ещё не на проверке, а пакет (самый новый пакет версии или `pkgId`) загружен и обработан; иначе отказывает и объясняет почему.

Режимы:

- `releaseType: "full"` (по умолчанию) — выпуск для всех сразу после одобрения или в `releaseTime`;
- `releaseType: "phased"` — выпуск для `phasedPercent` процентов пользователей с `phasedStart` до `phasedEnd`; у приложения уже должна быть выпущенная версия.

Аргументы: `appId`, `releaseType`, `releaseTime`, `phasedStart`, `phasedEnd`, `phasedPercent` (больше 0 и меньше 100, до двух знаков после запятой), `phasedDescription`, `pkgId`, `waitSeconds` (по умолчанию 0), `remark` (заметка для проверяющих, 10–300 символов), `dryRun`. Время — со смещением от UTC (`2026-12-01T10:00:00Z`, `2026-12-01T13:00:00+03:00`) и в будущем.

```json
{"appId": "100000001", "releaseType": "phased", "phasedStart": "2026-12-01T10:00:00Z", "phasedEnd": "2026-12-08T10:00:00Z", "phasedPercent": 10, "dryRun": true}
```

### release_manage

Меняет выпуск версии; результат видят пользователи AppGallery. Действия (`action`, обязателен):

| `action` | Что делает |
| --- | --- |
| `update_phased` | Меняет поэтапный выпуск: долю (только растёт и меньше 100), конец, описание, начало (пока выпуск не начался). |
| `suspend` | Приостанавливает идущий поэтапный выпуск. |
| `resume` | Возобновляет приостановленный. |
| `complete` | Выпускает версию для всех пользователей. |
| `set_release_time` | Переносит запланированный выпуск одобренной версии на `releaseTime`. |
| `release_now` | Выпускает одобренную версию, которая ждёт запланированного времени, сразу. |

Инструмент сначала читает текущее состояние и отказывает в переходах, которых API не допускает (меньшая доля, возобновление идущего выпуска, перенос времени у версии, которая не ждёт выпуска), ничего не меняя. Отменить поэтапный выпуск API не позволяет. Аргументы: `action`, `appId`, `phasedPercent`, `phasedStart`, `phasedEnd`, `phasedDescription`, `releaseTime`, `dryRun`.

```json
{"appId": "100000001", "action": "update_phased", "phasedPercent": 50, "dryRun": true}
```

### listing_export, listing_apply и image_sync

Страница приложения хранится в локальном каталоге в формате, похожем на fastlane:

```
<dir>/
  default_language.txt
  privacy_policy.txt
  developer_website.txt
  privacy_rights_url.txt
  .appgallery-images.json        # запись последней синхронизации изображений
  en-US/
    title.txt                    # название, до 64 символов
    short_description.txt        # краткое описание, до 80
    full_description.txt         # полное описание, до 8000
    release_notes.txt            # «Что нового», до 500
    images/icon.png
    images/screenshots/1.png ...
    videos/1.mp4 и обложка 1.jpg
```

Языки — коды AppGallery Connect (`en-US`, `ru-RU` и т. п.).

- **`listing_export`** (чтение) пишет страницу в новый или пустой каталог `dir`. Пишутся только непустые поля. Иконка и скриншоты скачиваются по умолчанию (`include_images`), видео — только с `include_videos: true`. Аргументы: `dir` (обязателен), `appId`, `include_images`, `include_videos`, `releaseType`.
- **`listing_apply`** (запись) применяет тексты из каталога: название, описания и «Что нового» по языкам, язык по умолчанию, политику конфиденциальности, сайт разработчика и адрес о правах на данные. Меняются только поля, файл которых есть и отличается; язык из каталога, которого нет у приложения, добавляется (нужен `title.txt`). Длины и коды языков проверяются до отправки. `dry_run` по умолчанию `true`: возвращает план с разницей, применяет — повторный вызов с `dry_run: false`. Языки, которые есть в AppGallery Connect, но нет в каталоге, только перечисляются; с `delete_missing_languages: true` они удаляются, для этого нужен сервер с `--allow-destructive` (язык по умолчанию не удаляется никогда). Аргументы: `dir` (обязателен), `appId`, `dry_run`, `apply_app_info` (по умолчанию `true`), `delete_missing_languages`, `releaseType`.
- **`image_sync`** (запись) загружает иконку, скриншоты и видео из каталога. AppGallery Connect заменяет все файлы одного вида на одном языке разом, поэтому единица изменения — вид на языке. Загружается только то, что изменилось с последней синхронизации (по SHA-256 из `.appgallery-images.json`) или у чего в AppGallery Connect изменилось число файлов. Замену в консоли с тем же числом файлов инструмент не видит: тогда передайте `force: true`. Проверки до загрузки: иконка PNG 216 × 216 до 2 МБ; от 3 до 5 скриншотов JPG или PNG до 2 МБ, 9:16 или 16:9, короткая сторона от 450 пикселей, одна ориентация; до трёх видео MP4 или MOV до 500 МБ с обложками JPG или PNG. `dry_run` по умолчанию `false`. Аргументы: `dir` (обязателен), `appId`, `languages`, `kinds` (`icon`, `screenshots`, `videos`), `force`, `dry_run`, `chineseMainland`, `releaseType`.

Изменения `listing_apply` и `image_sync` попадают в черновик версии и видны пользователям только после отправки на проверку и одобрения.

```json
{"appId": "100000001", "dir": "listing"}
```

### reviews_summary

Сводка отзывов одного приложения за любой период: распределение по оценкам (`byRating`), средняя оценка (`averageRating`; из статистики оценок AppGallery Connect, а если её нет — по собранным отзывам, `averageRatingSource` говорит откуда), число отзывов без ответа (`unanswered`) и последние отзывы с идентификаторами, обрезанными текстами и ответом разработчика. Данные автора не отдаются. Период длиннее шести месяцев режется на окна, которые принимает API. `complete: false` значит, что обход остановился на пределе страниц: сузьте период или фильтры. Отвечает на отзывы только отдельный `reply_review` (уровень удаления) по просьбе пользователя.

Аргументы: `countries` (обязателен; страны одного сайта AppGallery Connect), `appId`, `days` (по умолчанию 30, до 730) или `from`/`to` (`YYYY-MM-DD`), `ratings`, `languages` (вида `ru_RU`), `replied`, `maxReviews` (по умолчанию 50, до 500), `maxTextLength` (по умолчанию 500).

```json
{"appId": "100000001", "countries": ["RU"], "days": 90, "ratings": [1, 2]}
```

### report_download

Скачивает один отчёт приложения в файл (`save_to`) или возвращает его краткую сводку. Отчёты (`report`, обязателен):

| `report` | Что внутри | Период |
| --- | --- | --- |
| `installs` | показы, просмотры страницы, новые установки и обновления, удаления | до 180 дней |
| `in_app_purchases` | платящие пользователи и суммы в `currency` (USD, EUR, CNY) | до 180 дней |
| `paid_app` | покупки платного приложения | до 365 дней |
| `paid_app_details` | заказы платного приложения в одной стране (данные реальных пользователей), только CSV | до 180 дней |
| `install_failures` | ошибки установки с кодами и причинами | до 180 дней |

Период — `days` (по умолчанию 30 дней по вчерашний день UTC) или `from`/`to`; проверяется до запроса. С `save_to` сервер скачивает файл (только с хостов Huawei) и возвращает путь, размер и тип. Без `save_to` отчёт должен быть CSV: сервер читает его (до 32 МиБ) и возвращает `summary` — строки, колонки, итоги по основным метрикам (деньги — по валютам), первые `maxRows` строк; временный файл удаляется. `empty: true` — данных за период нет.

Аргументы: `report`, `appId`, `days`, `from`, `to`, `save_to`, `format` (`csv` по умолчанию или `excel`, Excel — только с `save_to`), `groupBy`, `countries`, `language` (язык колонок: `en-US`, `ru-RU`, `zh-CN`), `maxRows`, фильтры `businessType`, `appVersions`, `deviceName`, `downloadType`, `currency`, `dateType`, `orderId`, `orderStatus`. Аргумент, которого нет у выбранного отчёта, — ошибка с объяснением.

```json
{"appId": "100000001", "report": "installs", "days": 30, "countries": ["RU"], "save_to": "reports/installs.csv"}
```

## Пользовательские инструменты (tools.toml)

Частые запросы можно оформить своими инструментами: операция API с фиксированными аргументами и фильтром `jq`. Файл пользователя — `~/.config/appgallery-connect-mcp/tools.toml` (в Windows `%APPDATA%\appgallery-connect-mcp\tools.toml`), он читается всегда, если есть. Другие файлы — только явным `serve --tools-file`.

```toml
[[tools]]
name = "main_app_languages"
description = "Localized names of the main app"
operation = "get_app_info"
jq = "[.languages[] | {lang, appName}]"

[tools.args]
appId = "100000001"
```

- `operation` — имя инструмента операции (`get_app_info`) или её `operationId` (`publishing.appInfo.get`); список — `appgallery-connect-mcp tools list --toolsets all --allow-destructive`.
- `args` — фиксированные аргументы с теми же именами, что у инструмента операции. Они проверяются при загрузке и убираются из схемы; агент не может их переопределить.
- `jq` — необязательный фильтр ответа; фильтр из вызова агента применяется к его результату.
- Уровень доступа и набор инструмента — уровень и набор его операции: инструмент включается и выключается вместе с набором и не регистрируется выше уровня сервера.
- Имя не может совпадать с именами операций, составных и других встроенных инструментов.
- Если у операции есть `save_to`, он есть и у пользовательского инструмента, когда у того нет своего `jq`.

Проверка файлов — `appgallery-connect-mcp tools check`, список с пользовательскими инструментами — `tools list` ([CLI](cli.md#tools)).

## Частые задачи

| Задача | Инструменты |
| --- | --- |
| Какие приложения есть в кабинете | `search_apps`, `list_app_ids` |
| Что с приложением и версией | `app_overview`, `release_status` |
| Загрузить сборку | `package_upload` (`--allow-write`) |
| Отправить на проверку | `release_submit` (`--allow-destructive`) |
| Поэтапный выпуск | `release_submit` с `releaseType: "phased"`, затем `release_manage` |
| Отредактировать описание и «Что нового» | `listing_export` → правка файлов → `listing_apply` |
| Обновить скриншоты | `image_sync` |
| Отзывы и ответы | `reviews_summary`, `get_review`, `reply_review` (`--allow-destructive`) |
| Установки и покупки за период | `report_download` |
| Файл конфигурации для проекта | `config_download` |

Если подходящего инструмента не видно, агент находит операцию через `api_search`.
