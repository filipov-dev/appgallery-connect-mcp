# MCP-инструменты

Каждая операция AppGallery Connect API из встроенного снимка спецификации — отдельный MCP-инструмент: Publishing API, Upload Management API, Reports API, Comments API, PMS API (товары и подписки), Project Management API, Provisioning API (подпись HarmonyOS), Remote Configuration и серверный REST API App Linking, а также серверные API покупок в приложении HMS In-App Purchases (сервисы заказов и подписок, [набор `purchases`](#покупки-в-приложении-purchases)). Снимок ведётся по страницам справочника Huawei, потому что машинной спецификации у Huawei нет. Поверх операций есть шестнадцать [составных инструментов](#составные-инструменты), которые выполняют многошаговые сценарии за один вызов. Всегда доступны `api_search` и `api_request`. Для частых сценариев сервер отдаёт [промпты](#промпты).

Какие инструменты видит агент, задают уровень доступа (`--allow-write`, `--allow-destructive`) и наборы (`--toolsets`) сервера:

| Наборы | Чтение | Запись | Удаление |
| --- | ---: | ---: | ---: |
| по умолчанию (`apps`, `releases`, `reviews`) | 14 | 18 | 25 |
| все (`--toolsets all`) | 44 | 61 | 88 |

Числа включают `api_search` и `api_request` и соответствуют выводу `appgallery-connect-mcp tools list` этой версии. С динамическими наборами (по умолчанию после `connect`) при запуске их пять. Посмотреть список для своих настроек: `appgallery-connect-mcp tools list` с теми же флагами или `appgallery-connect-mcp serve --status`.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с флагом, который их включает.

| Уровень | Как включить | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение |
| write | `--allow-write` | плюс создание и изменение (`POST`, `PUT`, `PATCH`) |
| destructive | `--allow-destructive` (включает запись) | плюс удаление (`DELETE`) и действия с последствиями для пользователей AppGallery и денег |

Уровень операции по умолчанию — по методу: `GET` — чтение, `DELETE` — удаление, остальное — запись. Исключения заданы в файле-дополнении спецификации, а причина попадает в описание инструмента («Destructive: …»), поэтому агент её видит.

Уровень удаления, кроме `DELETE`, получают действия, последствия которых видят пользователи или которые затрагивают деньги:

| Действие | Инструменты |
| --- | --- |
| Отправка версии на проверку; после одобрения она выходит к пользователям | `submit_app`, `submit_app_with_file`, `release_submit` |
| Поэтапный выпуск: доля пользователей, пауза, выпуск для всех | `update_phased_release`, `release_manage` |
| Время выпуска одобренной версии, вплоть до выпуска сразу | `update_release_time`, `release_manage` |
| Публичный ответ на отзыв | `reply_review` |
| Товары и их цены | `update_product`, `batch_update_products` |
| Товары в продаже и снятие с продажи | `activate_products`, `deactivate_products` |
| Акции: создание, изменение, запуск и снятие | `create_promotion`, `update_promotion`, `release_promotions`, `remove_promotions` |
| Удаление сертификатов и устройств (запросом `POST`): профили с удалённым сертификатом перестают работать, сборки ими больше не подписать | `delete_certificates`, `delete_devices` |
| Удаление локализации и профиля подписи (`DELETE`) | `delete_app_language_info`, `delete_profile` |
| Новая версия Remote Configuration и откат к прежней: действует для пользователей сразу, без черновика и проверки | `update_remote_config`, `rollback_remote_config`, `remote_config_set` |
| Покупки пользователей (HMS IAP): подтверждение доставки товара, отмена, отсрочка оплаты, возврат и отзыв подписки | `confirm_product_purchase`, `cancel_subscription`, `defer_subscription`, `refund_subscription`, `revoke_subscription` |

Изменения до отправки на проверку — уровень записи: загрузка пакета, сведения о приложении, локализации, изображения. Пользователи видят их только после того, как версия отправлена и одобрена.

Исключения в обратную сторону:

- получение адреса загрузки файла (`GET`) — уровень записи: ответ выдаёт одноразовые учётные данные для загрузки;
- `POST`-методы, которые только читают, — уровень чтения: `list_product_groups`, `search_products`, `search_promotions`, `list_certificates`, а также `verify_product_purchase`, `get_subscription_purchase`, `list_cancelled_purchases`, `list_iap_orders`.

У каждого инструмента есть аннотации MCP `readOnlyHint` и `destructiveHint` по его уровню. Флаги командной строки важнее настроек профиля ([`serve`](cli.md#serve)). Уровень доступа сервера не расширяет роли API-клиента: AppGallery Connect всё равно проверяет их ([Роли](api-client.md#роли)).

### Динамические наборы

Клиенты, которые не откладывают загрузку инструментов, кладут описания всех зарегистрированных инструментов в контекст модели сразу. С `serve --dynamic-toolsets` (или `dynamic_toolsets = true` в профиле; `connect` включает это по умолчанию) сервер при запуске регистрирует только:

- `api_search` и `api_request`;
- `list_toolsets` — наборы с описанием, числом инструментов на уровне доступа сервера, примерами имён и признаком, включён ли набор;
- `enable_toolset` — включить набор (аргумент `toolset`, можно несколько через запятую);
- `disable_toolset` — выключить набор;
- наборы из `--toolsets` или профиля (без них — ни одного).

После `enable_toolset` и `disable_toolset` сервер отправляет клиенту `notifications/tools/list_changed`. Уровень доступа действует как обычно: включение набора не регистрирует инструменты выше него. Если клиент не перечитывает список инструментов, агент может вызвать ту же операцию через `api_request`.

## Приложения и аргументы

- Приложение адресуется числовым App ID (`appId`, например `100000001`), а не именем пакета. App ID по имени пакета отдаёт `list_app_ids`, список приложений кабинета — `search_apps`. Приложения по умолчанию можно сохранить в профиле ([Приложения по умолчанию](api-client.md#приложения-по-умолчанию)).
- Параметры пути, запроса и заголовков — обычные аргументы с именами, как в справочнике Huawei: `appId`, `lang`, `releaseType`. Часть параметров Huawei передаётся заголовками (например `appId` у PMS API): для агента это тоже обычный аргумент.
- Тело запроса — аргумент `body` (JSON-объект).
- Неизвестные аргументы отклоняются, обязательные аргументы и типы параметров проверяются до запроса. Внутри `body` проверяются только типы известных полей: справочник Huawei местами неточен в обязательных полях, решает AppGallery Connect.
- Повторяющиеся параметры запроса (`filterCondition` и `filterConditionValue` у отчётов) передаются JSON-массивом и уходят повтором `?a=1&a=2`. Списки, которые справочник описывает строкой через запятую (`countries` у `list_reviews`), передаются строкой.
- Описание каждого инструмента операции заканчивается ссылкой на его страницу в справочнике Huawei.

## Ответы и ошибки

Ответ — JSON-ответ AppGallery Connect API как есть, вместе с конвертом результата (`ret`, `error`). Единой постраничной выдачи у API нет: у разных групп свои параметры (например, `page` и `limit` у отзывов, `fromPage` и `pageSize` у проектов), они передаются обычными аргументами.

AppGallery Connect сообщает о многих ошибках с HTTP 200 и ненулевым кодом в теле ответа. Конверт у групп API разный:

| Группы API | Поле кода | Поле текста |
| --- | --- | --- |
| Publishing, Upload, Reports, Project, Provisioning, Remote Configuration, App Linking | `ret.code` | `ret.msg` |
| Comments | `ret.rtnCode` | `ret.rtnDesc` |
| PMS | `error.errorCode` | `error.errorMsg` |
| HMS IAP (набор `purchases`) | `responseCode` в корне | `responseMessage` |

Сервер проверяет код и возвращает такой ответ как ошибку инструмента (`isError: true`) с кодом и текстом Huawei. Успешный результат значит, что код был `0`. Ошибки HTTP (`4xx`, `5xx`) тоже возвращаются результатом с `isError: true`: статус, код и текст Huawei и подсказка, что делать ([Решение проблем](troubleshooting.md#ошибки-huawei-с-http-200)).

Результат больше `--max-response-bytes` (256 КиБ по умолчанию) — ошибка с подсказкой сузить запрос: меньше страница, строже фильтры, меньше языков или фильтр `jq`.

## Файлы и save_to

Некоторые ответы почти целиком состоят из секрета или временной ссылки. Сервер скрывает такие поля (`***`), а у инструмента появляется аргумент `save_to` — путь нового локального файла. С `save_to` сервер сам скачивает файл по ссылке (только с хостов Huawei) или записывает содержимое и возвращает агенту путь, размер, имя поля и тип: `saved: {path, bytes, field, content_type}`. Ссылка и содержимое в ответ не попадают.

| Инструмент | Что сохраняет |
| --- | --- |
| `get_download_report_url`, `get_iap_report_url`, `get_paid_app_report_url`, `get_paid_app_details_report_url`, `get_install_failure_report_url` | Файл отчёта по временной ссылке `fileURL`. |
| `get_app_config_file` | Файл конфигурации `agconnect-services.json` (поле `content`). |
| `list_certificates` | Файл сертификата (`.cer`) по временной ссылке; у списка — один файл, сузьте список до одного сертификата (`certIds`). Новый сертификат сохраняет `certificate_request`. |
| `create_profile`, `update_profile_devices`, `list_profiles` | Файл профиля подписи (`.p7b`) по временной ссылке; у списка — один файл, сузьте список до одного профиля (`provisionId`). |

Секрет приложения (`get_app_fingerprints`, поле `secret`) сервер не отдаёт никак: ни в ответе, ни в файл.

Составные инструменты, которые работают с файлами:

- `report_download`, `config_download`, `products_export` и `certificate_request` — сохраняют в `save_to` (`certificate_request` ещё читает файл CSR, `csr_file`);
- `listing_export` — пишет каталог страницы приложения (`dir`);
- `image_sync` — читает каталог и обновляет в нём файл `.appgallery-images.json`;
- `package_upload`, `listing_apply` и `products_apply` — только читают (`file`, `dir`).

Пути работают только в [разрешённых каталогах](security.md#локальные-файлы), существующие файлы не перезаписываются (кроме `.appgallery-images.json`, который `image_sync` заменяет новым). Путь проверяется до запроса к API. `save_to` и `jq` в одном вызове не сочетаются.

Шаги загрузки Upload Management API (адрес загрузки, загрузка по частям) не стали инструментами и не вызываются через `api_request`: их ответы — одноразовые адреса и заголовки загрузки. Пакеты загружает `package_upload`, изображения и видео — `image_sync`.

## api_search и api_request

- `api_search` ищет по всем операциям API без обращения к нему: инструменты операций (включая невключённые наборы и инструменты выше уровня доступа), исключённые операции и составные инструменты. Слова — на английском или русском: русские термины переводятся словарём («отзыв» → review, «подписка» → subscription, «выпуск» → release и т. д.), английские сравниваются по началу слова. Каждый результат говорит, в каком наборе инструмент, какого он уровня, можно ли вызвать его на этом сервере и что его включает (флаг доступа, набор, вызов через `api_request`). Аргументы: `query`, `toolset`, `limit` (по умолчанию 15, до 50); с `tool_name` — полное описание и схема одного инструмента.
- `api_request` вызывает любой путь AppGallery Connect API на хосте региона профиля в пределах уровня доступа сервера (наборы его не ограничивают): `method` (`GET` по умолчанию, `POST`, `PUT`, `PATCH`, `DELETE`), `path` от корня хоста, начинается с `/api/` (query можно после `?`), `query`, `headers` (заголовочные параметры, например `appId` у PMS API), `body`. Уровень берётся у операции, которой соответствует путь; для неизвестного пути — по методу. Полные адреса, `..`, `//`, заголовки `Authorization` и `client_id` и параметры с именами учётных данных отклоняются. Получение токена и шаги загрузки через `api_request` недоступны. Ошибки с HTTP 200 определяются так же, как у инструментов операций; секретные поля совпавшей операции скрываются. `save_to` у `api_request` нет.

Примеры: названия приложения по языкам и товар PMS API (`appId` у PMS API — заголовок), если наборы выключены:

```json
{"path": "/api/publish/v2/app-info", "query": {"appId": "100000001"}, "jq": "[.languages[] | {lang, appName}]"}
```

```json
{"path": "/api/pms/product-price-service/v1/manage/product", "query": {"productNo": "premium_month"}, "headers": {"appId": "100000001"}}
```

Сверьте имена параметров со схемой инструмента (`api_search` с `tool_name`): `api_request` их не проверяет.

## Фильтр jq

Инструменты операций с JSON-ответом, составные и пользовательские инструменты и `api_request` принимают необязательный аргумент `jq` — фильтр в диалекте [jaq](https://github.com/01mf02/jaq), например `[.languages[] | {lang, appName}]` для `get_app_info` или `[.appids[] | .value]` для `list_app_ids`.

- Фильтр применяется к телу ответа (вместе с конвертом результата) после вырезания секретов. Если что-то вырезано, пометка остаётся снаружи: `{"result": <результат фильтра>, "note": ...}`. Лимит `--max-response-bytes` действует на результат фильтра. Несколько результатов возвращаются массивом, ни одного — `[]`.
- Синтаксис проверяется до запроса к API. Ошибка выполнения фильтра после изменяющего запроса прямо говорит, что запрос выполнен и повторять его не нужно.
- Фильтру недоступны окружение, файлы и `input`. Сервер выполняет фильтры в дочернем процессе того же бинарника (скрытая команда `jq-worker`) с пустым окружением и таймаутом 10 секунд: зацикливание или переполнение стека завершают только этот процесс.

## Составные инструменты

Составной инструмент делает несколько запросов к API за один вызов. Ответ проходит ту же обработку, что и ответы операций (вырезание секретов, `jq`, лимит размера), и собирается из выбранных полей: адресов загрузки, временных ссылок и содержимого файлов с учётными данными в нём нет. `appId` у всех, где он есть, необязателен, если в профиле ровно одно приложение по умолчанию.

| Инструмент | Набор | Уровень | Что делает |
| --- | --- | --- | --- |
| [`search_apps`](#search_apps) | `apps` | чтение | Приложения кабинета с App ID, пакетами и проектами; поиск по пакету и названию. |
| [`app_overview`](#app_overview) | `apps` | чтение | Краткая сводка по приложению: версия, выпуск, рейтинг. |
| [`config_download`](#config_download) | `apps` | чтение | `agconnect-services.json` — в файл, без содержимого в ответе. |
| [`release_status`](#release_status) | `releases` | чтение | Состояние версии, проверки, выпуска и пакетов. |
| [`package_upload`](#package_upload) | `releases` | запись | Загрузка APK, AAB, RPK, APP или EXE и привязка к приложению. |
| [`release_submit`](#release_submit) | `releases` | удаление | Отправка версии на проверку: сразу, по времени или поэтапно. |
| [`release_manage`](#release_manage) | `releases` | удаление | Поэтапный выпуск и время выпуска. |
| [`listing_export`](#listing_export-listing_apply-и-image_sync) | `listing` | чтение | Страница приложения — в локальный каталог. |
| [`listing_apply`](#listing_export-listing_apply-и-image_sync) | `listing` | запись (удаление языков — удаление) | Тексты из каталога — в AppGallery Connect, с просмотром разницы. |
| [`image_sync`](#listing_export-listing_apply-и-image_sync) | `listing` | запись | Иконка, скриншоты и видео из каталога. |
| [`reviews_summary`](#reviews_summary) | `reviews` | чтение | Сводка отзывов за любой период. |
| [`report_download`](#report_download) | `reports` | чтение | Отчёт — в файл или краткой сводкой. |
| [`products_export`](#products_export-и-products_apply) | `products` | чтение | Товары, группы подписок, цены и акции — в JSON-файл. |
| [`products_apply`](#products_export-и-products_apply) | `products` | запись (цены, состояние и акции — удаление) | Файл товаров — в AppGallery Connect, с просмотром разницы. |
| [`certificate_request`](#certificate_request) | `provisioning` | запись | Сертификат подписи HarmonyOS по CSR из файла, файл сертификата — в `save_to`. |
| [`remote_config_set`](#remote_config_set) | `remote-config` | удаление | Изменение параметров и условий Remote Configuration по имени, с просмотром разницы. |

Аргументы ниже — в том виде, в каком их передаёт агент; обычно он сам подбирает их по просьбе пользователя. Полная схема — `api_search` с `tool_name`.

### search_apps

Список приложений кабинета с App ID, именами пакетов, названиями и проектами. Приложения профиля идут первыми (`default: true`). Список берётся из Project Management API (проекты и их приложения). Если этот API отказывает API-клиенту, инструмент ищет App ID для пакетов из `packageNames`, профиля и `query` (если он похож на имя пакета) через `list_app_ids`: тогда `source: "publishing"`, `projectsAvailable: false`, и находятся только приложения с известным именем пакета.

Аргументы: `query` (часть имени пакета или названия, без учёта регистра), `packageNames` (точные имена пакетов), `limit` (до 500, по умолчанию 50).

```json
{"query": "example"}
```

### app_overview

Краткая сводка по одному приложению: название на языке по умолчанию, коды языков, категории, платное или нет, число стран выпуска, возрастной рейтинг, версия в подготовке или на проверке с её состоянием, выпущенная версия, последний отзыв проверки, поэтапный выпуск и средняя оценка пользователей за 180 дней. Описаний, изображений и цен нет. Что не удалось прочитать (например, оценку), объясняют `notes`.

Аргументы: `appId`, `countries` (страны для оценки, одного сайта AppGallery Connect; по умолчанию `RU` для профиля региона `ru` или единственная страна выпуска).

```json
{"appId": "100000001", "countries": ["RU"]}
```

### config_download

Сохраняет файл конфигурации приложения `agconnect-services.json` в новый локальный файл. В файле учётные данные приложения, поэтому его содержимое агенту не отдаётся: в ответе путь, размер и имена ключей верхнего уровня без значений (`topLevelKeys`). Работает через Project Management API: при отказе по правам инструмент советует скачать файл в AppGallery Connect (Project settings → General information).

Аргументы: `save_to` (обязателен), `appId`.

```json
{"appId": "100000001", "save_to": "app/agconnect-services.json"}
```

### release_status

Состояние выпуска за один вызов: версия в подготовке или на проверке (название и код версии, состояние проверки и выпуска, последний отзыв проверки), выпущенная версия, ждёт ли одобренная версия запланированного выпуска, поэтапный выпуск (состояние, доля, начало и конец), последние пакеты и состояние сборки пакета текущей версии (`readyToSubmit`). Времени запланированного выпуска API не отдаёт.

Аргументы: `appId`, `maxPackages` (0–20, по умолчанию 5).

### package_upload

Загружает пакет и привязывает его к приложению. `file` — локальный APK, AAB, RPK, APP (HarmonyOS) или EXE (Windows). До запросов инструмент проверяет тип и размер (APK, APP, EXE — до 4 ГБ, AAB — до 150 МБ, RPK — до 30 МБ). Файл больше 100 МБ загружается частями с повторами. AAB по умолчанию ждёт, пока AppGallery Connect его обработает. На проверку инструмент не отправляет: это отдельный шаг (`release_submit`).

Ответ: имя, размер, тип и SHA-256 файла, `pkgId`, `packageStatus` (`ready`, `processing`, `failed`, `not_checked`, `unknown`), `readyForReview`, число частей и повторов.

Аргументы: `file` (обязателен), `appId`, `waitSeconds` (0–1800; по умолчанию 300 для AAB и 0 для остальных), `chineseMainland` (распространяется ли пакет в материковом Китае, по умолчанию `false`), `releaseType` (1 — полный выпуск, 3 — поэтапный), `versionName` и `displayName` (только и обязательно для EXE), `dryRun` (только проверить и описать загрузку).

```json
{"appId": "100000001", "file": "build/app-release.aab"}
```

### release_submit

Отправляет версию в подготовке на проверку и выпуск. Результат видят пользователи AppGallery: после одобрения версия выходит к ним, а отозвать отправку через API нельзя. Агент вызывает инструмент только по явной просьбе пользователя и сначала с `dryRun: true`. До отправки инструмент проверяет, что версия ещё не на проверке, а пакет (самый новый пакет версии или `pkgId`) загружен и обработан; иначе отказывает и объясняет почему.

Режимы:

- `releaseType: "full"` (по умолчанию) — выпуск для всех сразу после одобрения или в `releaseTime`;
- `releaseType: "phased"` — выпуск для `phasedPercent` процентов пользователей с `phasedStart` до `phasedEnd`; у приложения уже должна быть выпущенная версия.

Аргументы: `appId`, `releaseType`, `releaseTime`, `phasedStart`, `phasedEnd`, `phasedPercent` (больше 0 и меньше 100, до двух знаков после запятой), `phasedDescription`, `pkgId`, `waitSeconds` (по умолчанию 0), `remark` (заметка для проверяющих, 10–300 символов), `dryRun`. Время — со смещением от UTC (`2026-12-01T10:00:00Z`, `2026-12-01T13:00:00+03:00`) и в будущем.

```json
{"appId": "100000001", "releaseType": "phased", "phasedStart": "2026-12-01T10:00:00Z", "phasedEnd": "2026-12-08T10:00:00Z", "phasedPercent": 10, "dryRun": true}
```

### release_manage

Меняет выпуск версии; результат видят пользователи AppGallery. Действия (`action`, обязателен):

| `action` | Что делает |
| --- | --- |
| `update_phased` | Меняет поэтапный выпуск: долю (только растёт и меньше 100), конец, описание, начало (пока выпуск не начался). |
| `suspend` | Приостанавливает идущий поэтапный выпуск. |
| `resume` | Возобновляет приостановленный. |
| `complete` | Выпускает версию для всех пользователей. |
| `set_release_time` | Переносит запланированный выпуск одобренной версии на `releaseTime`. |
| `release_now` | Выпускает одобренную версию, которая ждёт запланированного времени, сразу. |

Инструмент сначала читает текущее состояние и отказывает в переходах, которых API не допускает (меньшая доля, возобновление идущего выпуска, перенос времени у версии, которая не ждёт выпуска), ничего не меняя. Отменить поэтапный выпуск API не позволяет. Аргументы: `action`, `appId`, `phasedPercent`, `phasedStart`, `phasedEnd`, `phasedDescription`, `releaseTime`, `dryRun`.

```json
{"appId": "100000001", "action": "update_phased", "phasedPercent": 50, "dryRun": true}
```

### listing_export, listing_apply и image_sync

Страница приложения хранится в локальном каталоге в формате, похожем на fastlane:

```
<dir>/
  default_language.txt
  privacy_policy.txt
  developer_website.txt
  privacy_rights_url.txt
  .appgallery-images.json        # запись последней синхронизации изображений
  en-US/
    title.txt                    # название, до 64 символов
    short_description.txt        # краткое описание, до 80
    full_description.txt         # полное описание, до 8000
    release_notes.txt            # «Что нового», до 500
    images/icon.png
    images/screenshots/1.png ...
    videos/1.mp4 и обложка 1.jpg
```

Языки — коды AppGallery Connect (`en-US`, `ru-RU` и т. п.).

- **`listing_export`** (чтение) пишет страницу в новый или пустой каталог `dir`. Пишутся только непустые поля. Иконка и скриншоты скачиваются по умолчанию (`include_images`), видео — только с `include_videos: true`. Аргументы: `dir` (обязателен), `appId`, `include_images`, `include_videos`, `releaseType`.
- **`listing_apply`** (запись) применяет тексты из каталога: название, описания и «Что нового» по языкам, язык по умолчанию, политику конфиденциальности, сайт разработчика и адрес о правах на данные. Меняются только поля, файл которых есть и отличается; язык из каталога, которого нет у приложения, добавляется (нужен `title.txt`). Длины и коды языков проверяются до отправки. `dry_run` по умолчанию `true`: возвращает план с разницей, применяет — повторный вызов с `dry_run: false`. Языки, которые есть в AppGallery Connect, но нет в каталоге, только перечисляются; с `delete_missing_languages: true` они удаляются, для этого нужен сервер с `--allow-destructive` (язык по умолчанию не удаляется никогда). Аргументы: `dir` (обязателен), `appId`, `dry_run`, `apply_app_info` (по умолчанию `true`), `delete_missing_languages`, `releaseType`.
- **`image_sync`** (запись) загружает иконку, скриншоты и видео из каталога. AppGallery Connect заменяет все файлы одного вида на одном языке разом, поэтому единица изменения — вид на языке. Загружается только то, что изменилось с последней синхронизации (по SHA-256 из `.appgallery-images.json`) или у чего в AppGallery Connect изменилось число файлов. Замену в консоли с тем же числом файлов инструмент не видит: тогда передайте `force: true`. Проверки до загрузки: иконка PNG 216 × 216 до 2 МБ; от 3 до 5 скриншотов JPG или PNG до 2 МБ, 9:16 или 16:9, короткая сторона от 450 пикселей, одна ориентация; до трёх видео MP4 или MOV до 500 МБ с обложками JPG или PNG. `dry_run` по умолчанию `false`. Аргументы: `dir` (обязателен), `appId`, `languages`, `kinds` (`icon`, `screenshots`, `videos`), `force`, `dry_run`, `chineseMainland`, `releaseType`.

Изменения `listing_apply` и `image_sync` попадают в черновик версии и видны пользователям только после отправки на проверку и одобрения.

```json
{"appId": "100000001", "dir": "listing"}
```

### products_export и products_apply

Товары, подписки и акции приложения хранятся в одном JSON-файле. Поля названы как в PMS API:

```json
{
  "format": "appgallery-products",
  "version": 1,
  "appId": "100000001",
  "subscriptionGroups": [
    {"groupId": "g1", "groupName": "Premium"}
  ],
  "products": [
    {
      "productNo": "coins_100",
      "purchaseType": "consumable",
      "status": "active",
      "defaultLocale": "en_US",
      "productName": "100 coins",
      "productDesc": "A pack of coins",
      "languages": [
        {"locale": "ru_RU", "productName": "100 монет", "productDesc": "Набор монет"}
      ],
      "defaultPrice": {"country": "CN", "currency": "CNY", "price": "600"},
      "prices": [
        {"country": "RU", "currency": "RUB", "price": "9900"}
      ]
    },
    {
      "productNo": "premium_month",
      "purchaseType": "auto_subscription",
      "status": "active",
      "defaultLocale": "en_US",
      "productName": "Premium",
      "productDesc": "Monthly subscription",
      "groupId": "g1",
      "subPeriod": 1,
      "subPeriodUnit": "M",
      "defaultPrice": {"country": "CN", "currency": "CNY", "price": "1200"}
    }
  ],
  "promotions": [
    {
      "promotionId": "p1",
      "productNo": "premium_month",
      "strategy": "introductory",
      "promotionStatus": "active",
      "state": "ongoing",
      "promotionTitle": "First month",
      "promotionDesc": "Half price",
      "defaultLocale": "en_US",
      "startDate": 1767225600000,
      "endDate": 1769904000000,
      "periodUnit": "M",
      "numberOfUnits": 1,
      "defaultPrice": {"country": "CN", "currency": "CNY", "price": "600"},
      "prices": [{"country": "RU", "price": "4900"}],
      "languages": [{"locale": "ru_RU", "title": "Первый месяц", "desc": "Половина цены"}]
    }
  ]
}
```

| Поле | Что это |
| --- | --- |
| `subscriptionGroups[]` | Группы подписок: `groupId` и название `groupName` (до 30 символов). Меняется только название; новые группы создаются в AppGallery Connect. |
| `products[].productNo` | Идентификатор товара: буквы, цифры, `_` и `.`, начинается с буквы или цифры. По нему запись файла сопоставляется с товаром. |
| `purchaseType` | `consumable`, `non_consumable` или `auto_subscription`. Не меняется. |
| `status` | `active` (в продаже) или `inactive` (снят с продажи). |
| `productName`, `productDesc`, `defaultLocale` | Название (до 55 символов) и описание (до 100) на языке по умолчанию; символ `\|` недопустим. |
| `languages[]` | Названия и описания на других языках: `locale` (`ru_RU`, `en_US`), `productName`, `productDesc`. |
| `defaultPrice` | Цена по умолчанию: страна, валюта и цена. От неё AppGallery Connect пересчитывает цены стран, которых нет в `prices`. Обязательна у товара в продаже и при ценах по странам. |
| `prices[]` | Цены по странам: `country` и `price`. `currency` — для справки: валюту страны задаёт AppGallery Connect. |
| `groupId`, `subPeriod`, `subPeriodUnit` | Только у подписок: группа, длительность и единица периода (`W`, `M`, `Y`). Не меняются. |
| `promotions[].promotionId` | Идентификатор акции. Без него запись — новая акция. |
| `strategy` | `trial` (бесплатный период) или `introductory` (вводная цена). Не меняется. |
| `promotionStatus` | `active` (акция запущена) или `inactive` (снята). Новая акция создаётся запущенной. |
| `state` | Ход акции: `ongoing`, `not_started`, `finished`. Только для чтения. |
| `startDate`, `endDate` | Начало и конец акции, миллисекунды Unix. |
| `periodUnit`, `numberOfUnits` | Период акции: `D`, `W`, `M`, `Y` и число. |
| `defaultPrice`, `prices[]` | Цена акции по умолчанию и по странам; у бесплатного периода в `prices` только страны. |
| `languages[]` | Название и описание акции на других языках: `locale`, `title`, `desc`. |
| `promotionType`, `offerId` | Вид акции и её код (только для приложений HarmonyOS NEXT), если они есть. |

Цены — в минимальных единицах валюты, как в PMS API: 1,99 USD — `199`, 99 RUB — `9900`. Цену можно записать строкой или целым числом.

- **`products_export`** (чтение) пишет файл `save_to` (только новый). Выгружаются группы подписок, товары в продаже и снятые с продажи (удалённые — нет) и акции, кроме удалённых и закончившихся (закончившиеся — с `include_finished_promotions: true`). В ответе только путь, размер и счётчики. Аргументы: `save_to` (обязателен), `appId`, `country`, `include_finished_promotions`.
- **`products_apply`** (запись) сравнивает файл с AppGallery Connect и меняет только то, что отличается. `dry_run` по умолчанию `true`: возвращает план, где у каждого изменения есть старые и новые значения и уровень доступа; применяет — повторный вызов с `dry_run: false`. Записи, которых нет в файле, не трогаются; языки и цены стран, которых нет у записи, остаются как есть. Названия и описания товаров, их языки и названия групп — уровень записи. Цены, новый товар, активация и деактивация, любое изменение акции, новая акция, её запуск и снятие — уровень удаления: без `--allow-destructive` применение такого плана отклоняется до первого изменения, с перечнем этих правок, а план с `dry_run` показывается. С `force_existing_subscribers: true` новая цена подписки применяется и к текущим подписчикам. Аргументы: `file` (обязателен), `appId` (по умолчанию — из файла), `dry_run`, `force_existing_subscribers`, `country`.

До любых запросов `products_apply` проверяет файл: цены — положительные целые, коды стран из двух заглавных букв и валют из трёх, длины названий, бесплатный период — 3 дня, 1 или 2 недели, 1, 2, 3 или 6 месяцев или год, у вводной цены есть цена по умолчанию и цены по странам. После чтения текущего состояния и до первого изменения — то, для чего нужен AppGallery Connect: тип, группа и период товара и тип акции не меняются, акции бывают только у подписок, период вводной цены кратен периоду подписки и не длиннее 12 месяцев, валюта страны совпадает с валютой в AppGallery Connect. Правил пересчёта цен между странами инструмент не проверяет. Сбой на середине возвращает ошибку со списком уже применённого.

`country` нужен поиску товаров PMS API (по нему пересчитываются цены в списке, в файл они не попадают), по умолчанию `CN`.

```json
{"appId": "100000001", "file": "products.json", "dry_run": true}
```

### reviews_summary

Сводка отзывов одного приложения за любой период: распределение по оценкам (`byRating`), средняя оценка (`averageRating`; из статистики оценок AppGallery Connect, а если её нет — по собранным отзывам, `averageRatingSource` говорит откуда), число отзывов без ответа (`unanswered`) и последние отзывы с идентификаторами, обрезанными текстами и ответом разработчика. Данные автора не отдаются. Период длиннее шести месяцев режется на окна, которые принимает API. `complete: false` значит, что обход остановился на пределе страниц: сузьте период или фильтры. Отвечает на отзывы только отдельный `reply_review` (уровень удаления) по просьбе пользователя.

Аргументы: `countries` (обязателен; страны одного сайта AppGallery Connect), `appId`, `days` (по умолчанию 30, до 730) или `from`/`to` (`YYYY-MM-DD`), `ratings`, `languages` (вида `ru_RU`), `replied`, `maxReviews` (по умолчанию 50, до 500), `maxTextLength` (по умолчанию 500).

```json
{"appId": "100000001", "countries": ["RU"], "days": 90, "ratings": [1, 2]}
```

### report_download

Скачивает один отчёт приложения в файл (`save_to`) или возвращает его краткую сводку. Отчёты (`report`, обязателен):

| `report` | Что внутри | Период |
| --- | --- | --- |
| `installs` | показы, просмотры страницы, новые установки и обновления, удаления | до 180 дней |
| `in_app_purchases` | платящие пользователи и суммы в `currency` (USD, EUR, CNY) | до 180 дней |
| `paid_app` | покупки платного приложения | до 365 дней |
| `paid_app_details` | заказы платного приложения в одной стране (данные реальных пользователей), только CSV | до 180 дней |
| `install_failures` | ошибки установки с кодами и причинами | до 180 дней |

Период — `days` (по умолчанию 30 дней по вчерашний день UTC) или `from`/`to`; проверяется до запроса. С `save_to` сервер скачивает файл (только с хостов Huawei) и возвращает путь, размер и тип. Без `save_to` отчёт должен быть CSV: сервер читает его (до 32 МиБ) и возвращает `summary` — строки, колонки, итоги по основным метрикам (деньги — по валютам), первые `maxRows` строк; временный файл удаляется. `empty: true` — данных за период нет.

Аргументы: `report`, `appId`, `days`, `from`, `to`, `save_to`, `format` (`csv` по умолчанию или `excel`, Excel — только с `save_to`), `groupBy`, `countries`, `language` (язык колонок: `en-US`, `ru-RU`, `zh-CN`), `maxRows`, фильтры `businessType`, `appVersions`, `deviceName`, `downloadType`, `currency`, `dateType`, `orderId`, `orderStatus`. Аргумент, которого нет у выбранного отчёта, — ошибка с объяснением.

```json
{"appId": "100000001", "report": "installs", "days": 30, "countries": ["RU"], "save_to": "reports/installs.csv"}
```

### certificate_request

Запрашивает сертификат подписи HarmonyOS по запросу на подпись (CSR) из локального файла и сохраняет файл сертификата (`.cer`) в `save_to`. CSR пользователь создаёт вместе с ключом подписи, например в DevEco Studio (Build → Generate Key and CSR). До запроса инструмент проверяет файл: текст до 16 КиБ, ровно один блок PEM `CERTIFICATE REQUEST` или `NEW CERTIFICATE REQUEST` с base64 внутри, не длиннее 2048 символов. Файл с приватным ключом (любой блок `… PRIVATE KEY`) отклоняется целиком: ключ никуда не отправляется и в ответ не попадает. Сам запрос сертификата (`provisioning.cert.create`) не стал инструментом и закрыт для `api_request`: он принимает CSR строкой, а сервер берёт CSR только из файла.

Каждый вызов создаёт новый сертификат, а число сертификатов в кабинете ограничено, поэтому запрос не повторяется ни при ошибке сети, ни после успеха. Ссылка на файл живёт около пяти минут: передавайте `save_to` в том же вызове. Если сертификат создан, а файл сохранить не удалось, это не ошибка: пометка говорит, как получить файл позже — `list_certificates` с `certIds` и `save_to`.

Ответ: `certificate` (`id`, `certName`, `certType`, `createTime`, `expireTime`), `saved` (путь, размер, тип), `csrFile`, `notes`. Ссылки на файл в ответе нет.

Аргументы: `csr_file` (обязателен), `certName` (обязателен, до 100 символов, уникален в кабинете), `certType` (обязателен: 1 — отладочный, 2 — выпускной, 3 — для внутреннего распространения, 4 — бинарный, только по разрешению Huawei), `save_to`.

```json
{"csr_file": "signing/debug.csr", "certName": "debug-2026", "certType": 1, "save_to": "signing/debug.cer"}
```

### remote_config_set

Меняет параметры Remote Configuration одного приложения по имени: значение по умолчанию, значение для условия, описание, новый параметр, удаление параметра, а также добавляет, заменяет и удаляет условия. Сервер сам читает текущую конфигурацию (`get_remote_config`), применяет изменения и возвращает разницу: `changes.parameters` и `changes.filters` с действием (`add`, `update`, `delete`) и состоянием до и после, `version` прочитанной версии и `request` — что будет записано. Параметры и условия, которых нет в аргументах, уходят обратно такими, какими их хранит AppGallery Connect, поэтому скрытые в ответах значения (`***`) не затираются; новые значения с `***` отклоняются.

По умолчанию `dry_run: true`: только разница, без записи. С `dry_run: false` (нужен `--allow-destructive`) инструмент записывает новую версию `update_remote_config` с номером прочитанной версии. Если конфигурацию за это время изменил кто-то другой, AppGallery Connect отвечает кодом `204083201`, и инструмент говорит, что ничего не записано: повторите с `dry_run: true`. `baseVersion` — версия, которую пользователь видел в разнице: если текущая другая, запись не делается. В ответе после записи — `newVersion` и подсказка, как откатить изменение.

Аргументы: `productId` (Project ID; необязателен, если в профиле ровно один API-клиент проекта), `appId`, `parameters[]` (`name`, `value`, `useSdkValue`, `description`, `conditions` — значения по имени условия: строка, `{"useSdkValue": true}` или `null`, чтобы убрать значение, `delete`), `filters[]` (условия целиком, как их отдаёт `get_remote_config`), `removeFilters[]`, `baseVersion`, `dry_run`. Условие, которое ещё используется параметром, удалить нельзя: уберите и его значения.

```json
{"appId": "100000001", "parameters": [{"name": "new_checkout", "value": "true", "conditions": {"beta": "false"}}]}
```

## Подпись HarmonyOS (provisioning)

Набор `provisioning` выключен по умолчанию: его включают `--toolsets provisioning` (или `all`), настройка профиля или `enable_toolset`. Инструменты:

| Инструмент | Уровень | Что делает |
| --- | --- | --- |
| `list_certificates` | чтение (`POST`) | Сертификаты, по типу (`certType`) или идентификаторам (`certIds`); файл одного сертификата — `save_to`. |
| `certificate_request` | запись | Новый сертификат по CSR из файла, файл — `save_to`. |
| `delete_certificates` | удаление | Удаляет сертификаты: профили с ними перестают работать. |
| `list_devices` | чтение | Отладочные и тестовые устройства: поиск по имени, страницы `fromRecCount` и `maxReqCount` (до 100). |
| `add_devices` | запись | Добавляет до 1000 устройств по UDID; в ответе число добавленных и причины отказов. |
| `delete_devices` | удаление | Удаляет устройства; занятые профилями устройства не удаляются (код `204144769`). |
| `list_profiles` | чтение | Профили приложения (`appId`, `provisionId` — заголовками); файл одного профиля — `save_to`. |
| `create_profile` | запись | Профиль для приложения и сертификата: отладочный, выпускной, для внутреннего распространения или для выпуска на заданных устройствах (`deviceIdList`). |
| `update_profile_devices` | запись | Заменяет устройства отладочного профиля или профиля для заданных устройств; новый файл — `save_to`. |
| `delete_profile` | удаление | Удаляет профиль: сборки им больше не подписать. |

Обычный порядок для отладки на устройстве: `add_devices` → `certificate_request` (тип 1) → `create_profile` (тип 1, `certId` и `deviceIdList`) с `save_to` → подпись сборки сертификатом и профилем. Файлы сертификатов и профилей не секретны, но ключ, из которого сделан CSR, держите при себе: не передавайте его агенту и не коммитьте.

Ссылки на файлы сертификатов и профилей скрываются во всех ответах, в том числе `api_request`; файлы скачиваются только с хостов Huawei.

## Remote Configuration (remote-config)

Набор `remote-config` выключен по умолчанию: его включают `--toolsets remote-config` (или `all`), настройка профиля или `enable_toolset`. Remote Configuration — серверный API сервиса проекта: запросы подписывает не API-клиент команды профиля, а API-клиент проекта, который добавляет `auth project add` ([Для Remote Configuration](api-client.md#для-remote-configuration)). Проект задаёт обязательный аргумент `productId` (Project ID), приложение — `appId`; оба уходят заголовками. Если для проекта нет API-клиента, сервер не отправляет запрос и говорит, какую команду выполнить.

| Инструмент | Уровень | Что делает |
| --- | --- | --- |
| `get_remote_config` | чтение | Текущая конфигурация или версия `version`: параметры (`configItems`), условия (`filters`) и сведения о версии. |
| `list_remote_config_versions` | чтение | История версий: период `startTime`/`endTime`, страницы `fromPage` и `pageSize`. |
| `update_remote_config` | удаление | Записывает новую версию из тела запроса (`version` — номер текущей версии). Похоже, тело заменяет конфигурацию целиком: передавайте все параметры и условия. |
| `rollback_remote_config` | удаление | Делает текущей одну из прежних версий (до 300 версий за последние 90 дней). |
| `remote_config_set` | удаление | Изменения по имени с просмотром разницы ([remote_config_set](#remote_config_set)). |

Новая версия действует для пользователей приложения сразу, как только их устройства получат конфигурацию; черновика и проверки нет. Поэтому запись и откат — уровень удаления, а агент меняет конфигурацию через `remote_config_set` с `dry_run: true` и показывает разницу пользователю. `update_remote_config` и `api_request` к тому же пути отклоняют тело со скрытыми значениями (`***`).

Лимит Huawei — 5 запросов в секунду и 1000 в час с одного IP-адреса. Роли API-клиента проекта, которым справочник разрешает эти операции: Administrator, App administrator, Development, Operations.

## Ссылки App Linking (app-linking)

Набор `app-linking` — серверный REST API App Linking. Он выключен по умолчанию: его включают `--toolsets app-linking` (или `all`), настройка профиля или `enable_toolset`. Оба инструмента — уровня записи (`--allow-write`):

| Инструмент | Что делает |
| --- | --- |
| `create_short_link` | Короткая ссылка кроссплатформенной ссылки: из длинной ссылки (`longUrl`) или из описания (`linkInfo`: префикс, deep link, приложения Android, HarmonyOS и iOS, карточка для соцсетей, метки кампании). Длина суффикса `suffixLength` (`SHORT` или `LONG`), срок жизни `expireTime` в секундах (больше 300, по умолчанию два года). В ответе `shortUrl` и `testUrl` для предпросмотра. |
| `create_unified_link` | Единая ссылка на скачивание: одна ссылка открывает приложение в магазине устройства (App Store, AppGallery, другой магазин Android) и ссылку по умолчанию на остальных устройствах. В ответе `shortUrl`. |

- App Linking — сервис проекта: запросы подписывает API-клиент проекта, а не команды. Проект — аргумент `productId` (заголовок запроса); клиент этого проекта сначала добавляют в профиль `auth project add` ([API-клиент проекта](api-client.md#api-клиент-проекта)). Без него запрос не отправляется.
- Префикс ссылок (`uriPrefix`, например `https://example.drcn.agconnect.link`) заводится заранее в AppGallery Connect: проект → App Linking.
- Ссылки, созданные через API, не видны в AppGallery Connect, и API не умеет их перечислять, менять и удалять. Ссылка публичная: открыть её может любой, кому она попала, пока не истёк срок. Лимиты Huawei: 100 000 коротких ссылок в день и 2000 единых ссылок на проект.
- Статистики переходов, списка ссылок и удаления в серверном API нет; их смотрят в консоли App Linking (только для ссылок, созданных там).

## Покупки в приложении (purchases)

Набор `purchases` — серверные API HMS In-App Purchases: сервис заказов (разовые товары) и сервис подписок. Это не AppGallery Connect API: запросы идут на хосты `orders-*` и `subscr-*` сайта профиля (`orders-drru.iap.cloud.huawei.ru` для России, `orders-drcn.iap.cloud.huawei.com.cn` для Китая и т. д.) и подписываются не API-клиентом, а токеном уровня приложения. Его сервер получает по секрету приложения, который пользователь сохраняет командой [`auth app-secret set`](cli.md#auth-app-secret-set). У каждого инструмента обязательный аргумент `appId`: он выбирает секрет и в Huawei не отправляется. Без сохранённого секрета инструмент отвечает ошибкой с командой, которая его добавляет, и запрос не отправляет. `api_request` эти операции не вызывает.

Набор выключен по умолчанию: его включают `--toolsets purchases` (или `all`), настройка профиля или `enable_toolset`.

| Инструмент | Уровень | Что делает |
| --- | --- | --- |
| `verify_product_purchase` | чтение (`POST`) | Проверяет токен покупки разового товара и возвращает данные покупки. Проверить можно только последний токен товара: после подтверждения и новой покупки старый токен даёт код `12`. |
| `confirm_product_purchase` | удаление | Подтверждает доставку расходуемого товара: без этого пользователь не купит его снова. Отменить подтверждение нельзя. |
| `list_cancelled_purchases` | чтение (`POST`) | Отменённые и возвращённые покупки за последние 30 дней (`type`: 0 — разовые товары, 1 — и подписки), до 1000 записей на страницу. |
| `list_iap_orders` | чтение (`POST`) | Заказы оплат и возвратов за период не длиннее 48 часов (`startAt`, `endAt` в миллисекундах UTC). |
| `get_subscription_purchase` | чтение (`POST`) | Последние данные подписки: действует ли она сейчас (`subIsvalid`), когда кончается период (`expirationDate`). |
| `cancel_subscription` | удаление | Отменяет продление: подписка действует до конца оплаченного периода. |
| `defer_subscription` | удаление | Переносит дату следующего списания на 1–365 дней: до неё пользователь пользуется подпиской бесплатно. |
| `refund_subscription` | удаление | Возвращает последний платёж подписки, не отменяя её. |
| `revoke_subscription` | удаление | Отзывает подписку сразу и возвращает последний платёж. |

`purchaseToken` и `subscriptionId` берутся из данных покупки (InAppPurchaseData), которые клиент IAP отдаёт приложению после покупки или запроса покупок, с бэкенда приложения или из `list_cancelled_purchases`. Вернуть деньги через эти API можно только за подписку; разовые товары возвращаются через поддержку Huawei. Списки длиннее страницы продолжаются так: `continuationToken` из ответа передаётся в `body` следующего вызова.

Что сервер меняет в ответе:

- `purchaseTokenData`, `inappPurchaseData` и `cancelledPurchaseList` Huawei отдаёт JSON-строкой внутри JSON. Сервер разбирает их и отдаёт агенту объект (или массив). Строка, которая не разбирается, остаётся текстом, и пометка `note` говорит об этом.
- `dataSignature` и `signatureAlgorithm` сервер убирает с пометкой `note`: подпись покрывает исходную строку, после разбора её не проверить. Если подпись нужна, её проверяет бэкенд приложения своим запросом.
- Токены покупок не скрываются: агент передаёт их в следующие вызовы. Секрет приложения и токен уровня приложения в ответы не попадают никогда.

Ошибки сервис сообщает кодом `responseCode` в корне ответа с HTTP 200: сервер возвращает такой ответ ошибкой инструмента с кодом и текстом Huawei. Частые коды: `5` — IAP не включён для приложения, `6` — сбой на стороне Huawei, `8` — пользователь не владеет товаром, `9` — покупка уже подтверждена, `11` — проблема с учётной записью пользователя, `12` — заказа нет или токен не последний.

Данные покупок и заказов — персональные данные покупателей ([Безопасность](security.md#покупки-в-приложении)). Инструменты уровня удаления меняют деньги и доступ настоящих пользователей: агент вызывает их только по явной просьбе пользователя.

### IAP Kit для HarmonyOS 5 и новее

Покупки в приложениях на HarmonyOS 5 и новее идут через IAP Kit, у которого свой REST API (`iap.cloud.huawei.com`): запросы подписываются JWT ES256 ключом IAP Kit (`.p8`, Key ID, Issuer ID), а ответы приходят в формате JWS, который нужно проверять по цепочке сертификатов Huawei. Сервер этого пока не умеет: операции IAP Kit (статус заказа и подписки, подтверждение доставки, отсрочка продления, заказы, история покупок, уведомления, ответ на запрос возврата) есть только в `api_search`, с пометкой «not callable» и объяснением. Инструменты набора `purchases` работают с покупками HMS IAP (Android и HarmonyOS 4 и раньше); для приложений на HarmonyOS 5 эти запросы делает сервер самого приложения.

## Промпты

Сервер отдаёт промпты (`prompts/list`) — готовые сценарии для частых задач. Промпт только описывает шаги для агента и называет инструменты; сам он запросов не делает. В начале текста промпт называет наборы инструментов и уровень доступа, который нужен на весь сценарий, и сравнивает его с уровнем сервера:

- инструменты выше уровня сервера помечены в тексте как недоступные: агент выполняет то, что можно, готовит остальное (тексты, значения, аргументы) и говорит пользователю, какой флаг нужен или что сделать в AppGallery Connect;
- перед действиями уровня удаления (отправка на проверку, изменение поэтапного выпуска, ответ на отзыв, изменения товаров и цен) агент получает явное подтверждение пользователя и сначала вызывает инструмент с `dryRun: true`;
- если нужного набора нет среди включённых, промпт с динамическими наборами просит агента включить его через `enable_toolset`, а без них — попросить пользователя перезапустить сервер с `--toolsets`;
- `appId` необязателен: если в профиле одно приложение по умолчанию, промпт берёт его, иначе агент спрашивает пользователя или находит приложение через `search_apps`.

| Промпт | Аргументы | Наборы | Уровень для всего сценария | Сценарий |
| --- | --- | --- | --- | --- |
| `prepare_release` | `appId`, `file`, `release_type` | `releases`, `listing`, `apps` | удаление | Проверить состояние версии, загрузить пакет, обновить «Что нового» на всех языках, проверить готовность и отправить на проверку только после подтверждения (`release_submit`). |
| `phased_release` | `appId`, `steps`, `countries` | `releases`, `reviews`, `reports`, `apps` | удаление | Вести поэтапный выпуск: между шагами смотреть отзывы и ошибки установки, расширять долю пользователей (по умолчанию 1, 5, 10, 20, 50 %, затем всем), приостановить при росте проблем (`release_manage`). |
| `triage_reviews` | `appId`, `countries`, `days` | `reviews`, `releases`, `apps` | удаление | Сводка отзывов за период, группировка по темам, оценкам и версиям, черновики ответов; ответ публикуется (`reply_review`) только после одобрения точного текста. |
| `products_overview` | `appId`, `country` | `products`, `apps` | чтение | Товары, группы подписок и акции с состоянием и ценами для страны, проблемы. Изменения — отдельными запросами после подтверждения; операции агент находит через `api_search`. |
| `monthly_report` | `appId`, `month`, `currency`, `save_dir` | `reports`, `apps` | чтение | Установки, покупки, продажи платного приложения и ошибки установки за месяц (`report_download`). |
| `listing_update` | `appId`, `dir` | `listing`, `releases`, `apps` | запись | Сохранить копию страницы приложения, применить тексты и изображения из каталога (`listing_apply`, `image_sync`), показать разницу и применить после подтверждения. |

Регистрируются промпты, которые хоть что-то делают при уровне доступа сервера: `listing_update` требует `--allow-write` и без него не попадает в `prompts/list`, остальные доступны и только на чтение. Без `--allow-destructive` промпты с уровнем «удаление» работают в режиме чтения: проверяют состояние, готовят черновики и шаги, но отправку, изменение выпуска и ответы на отзывы оставляют пользователю. Обязателен только `dir` у `listing_update`; остальное агент спросит у пользователя или возьмёт по умолчанию.

## Пользовательские инструменты (tools.toml)

Частые запросы можно оформить своими инструментами: операция API с фиксированными аргументами и фильтром `jq`. Файл пользователя — `~/.config/appgallery-connect-mcp/tools.toml` (в Windows `%APPDATA%\appgallery-connect-mcp\tools.toml`), он читается всегда, если есть. Другие файлы — только явным `serve --tools-file`.

```toml
[[tools]]
name = "main_app_languages"
description = "Localized names of the main app"
operation = "get_app_info"
jq = "[.languages[] | {lang, appName}]"

[tools.args]
appId = "100000001"
```

- `operation` — имя инструмента операции (`get_app_info`) или её `operationId` (`publishing.appInfo.get`); список — `appgallery-connect-mcp tools list --toolsets all --allow-destructive`.
- `args` — фиксированные аргументы с теми же именами, что у инструмента операции. Они проверяются при загрузке и убираются из схемы; агент не может их переопределить.
- `jq` — необязательный фильтр ответа; фильтр из вызова агента применяется к его результату.
- Уровень доступа и набор инструмента — уровень и набор его операции: инструмент включается и выключается вместе с набором и не регистрируется выше уровня сервера.
- Имя не может совпадать с именами операций, составных и других встроенных инструментов.
- Если у операции есть `save_to`, он есть и у пользовательского инструмента, когда у того нет своего `jq`.

Проверка файлов — `appgallery-connect-mcp tools check`, список с пользовательскими инструментами — `tools list` ([CLI](cli.md#tools)).

## Частые задачи

| Задача | Инструменты |
| --- | --- |
| Какие приложения есть в кабинете | `search_apps`, `list_app_ids` |
| Что с приложением и версией | `app_overview`, `release_status` |
| Загрузить сборку | `package_upload` (`--allow-write`) |
| Отправить на проверку | `release_submit` (`--allow-destructive`) |
| Поэтапный выпуск | `release_submit` с `releaseType: "phased"`, затем `release_manage` |
| Отредактировать описание и «Что нового» | `listing_export` → правка файлов → `listing_apply` |
| Обновить скриншоты | `image_sync` |
| Отзывы и ответы | `reviews_summary`, `get_review`, `reply_review` (`--allow-destructive`) |
| Установки и покупки за период | `report_download` |
| Файл конфигурации для проекта | `config_download` |
| Сертификат и профиль подписи HarmonyOS | `add_devices`, `certificate_request`, `create_profile` (`--toolsets provisioning`, `--allow-write`) |
| Короткая ссылка для рассылки или единая ссылка на магазины | `create_short_link`, `create_unified_link` (`--toolsets app-linking`, `--allow-write`, API-клиент проекта) |
| Названия и цены товаров, акции подписок | `products_export` → правка файла → `products_apply` |
| Включить флаг или поменять параметр Remote Configuration | `remote_config_set` с `dry_run: true`, затем с `dry_run: false` (`--toolsets remote-config`, `--allow-destructive`, `auth project add`) |
| Откатить Remote Configuration | `list_remote_config_versions`, `rollback_remote_config` (`--allow-destructive`) |
| Проверить покупку или подписку пользователя | `verify_product_purchase`, `get_subscription_purchase` (`--toolsets purchases`, секрет приложения) |
| Готовый сценарий целиком | промпты `prepare_release`, `phased_release`, `triage_reviews`, `products_overview`, `monthly_report`, `listing_update` ([Промпты](#промпты)) |

Если подходящего инструмента не видно, агент находит операцию через `api_search`.
