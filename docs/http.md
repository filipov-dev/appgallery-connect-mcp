# HTTP-режим и Docker

Обычно MCP-клиент сам запускает `appgallery-connect-mcp serve` на машине агента и говорит с ним через stdio. HTTP-режим (`serve --http`) нужен, когда у клиента нет локального бинарника (облачный агент, клиент только с удалёнными MCP-серверами) или когда один сервер с одним API-клиентом кабинета обслуживает нескольких агентов.

Идентификатор и секрет API-клиента при этом остаются на стороне сервера и по сети к нему не приходят. Клиенты приходят со своими токенами доступа к MCP; у каждого токена свой уровень доступа и наборы инструментов. Правила безопасности — в [Безопасности](security.md#http-режим).

## Как это устроено

- `POST /mcp` — Streamable HTTP без сессий: каждый запрос обрабатывается отдельно, ответы — `application/json`. `GET /health` — проверка готовности без токена.
- Адрес по умолчанию — `127.0.0.1:8769` (`--listen`), то есть только локальные подключения.
- Учётные данные API-клиента — из профиля `--profile` в системном хранилище машины сервера, как у stdio-сервера ([API-клиент](api-client.md)). В контейнере системного хранилища нет: учётные данные приходят файлом секрета `--secret-file` с правами `0600` или `0400` ([Файл секрета](#файл-секрета)). Access token Huawei сервер получает сам и держит только в памяти; один на всех клиентов. API-клиенты проектов (для наборов `remote-config` и `app-linking`) берутся только из профиля: их добавляет `auth project add` на машине сервера, а с `--secret-file` их нет, и операции Remote Configuration и App Linking отвечают ошибкой с подсказкой для оператора, без запроса к API.
- Клиент присылает `Authorization: Bearer <токен доступа>`. Сервер знает только SHA-256 токенов (файл `--access-tokens`): без токена, с чужим или коротким токеном — `401`.
- Уровень доступа сервера — потолок для токенов: токен с уровнем выше — ошибка запуска. С учётными данными из хранилища (`--profile`) уровень сервера — права профиля, как у stdio-сервера (на macOS — одобренные), а `--allow-write` и `--allow-destructive` их только сужают: флаг сверх профиля — ошибка запуска. С `--secret-file` (контейнер, профиля может не быть) уровень задают одни флаги. `--toolsets` — наборы для токенов, у которых своих наборов нет.
- Динамических наборов (`--dynamic-toolsets`) и `--status` в HTTP-режиме нет. Пользовательские инструменты — только из `--tools-file`: файл `tools.toml` из каталога настроек не читается.
- У сервера нет доступа к файлам машины агента. Инструменты с файлами (загрузка пакетов, экспорт и применение страницы приложения, синхронизация изображений, отчёты, файл конфигурации, `save_to`) работают только с каталогами сервера: `allow_path` профиля (суженные `--allow-path`), а с `--secret-file` — каталоги `--allow-path`; без них они не регистрируются. Рабочий и временный каталоги сервера в HTTP-режиме не разрешаются.

## Токены доступа

Токен доступа — случайная строка не короче 32 символов, которую оператор сервера выдаёт клиенту. Это не секрет API-клиента и не access token Huawei: токен только пускает к серверу. Создайте токен и его хеш:

```bash
TOKEN="$(openssl rand -hex 32)"
printf '%s' "$TOKEN" | sha256sum      # macOS: shasum -a 256
```

Токен отдайте клиенту (в конфигурацию его MCP-клиента), в файл сервера запишите только хеш:

```toml
# tokens.toml
[[tokens]]
name = "ci"              # имя в логах сервера: A-Z, a-z, 0-9, ".", "_", "-", до 64 символов
sha256 = "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
# access = "read"        # read (по умолчанию) | write | destructive
# toolsets = ["apps", "releases", "reviews", "reports"]   # по умолчанию --toolsets сервера

[[tokens]]
name = "release-bot"
sha256 = "60303ae22b998861bce3b28f33eec1be758a213c86c93c076dbe9f558c11c752"
access = "write"
toolsets = ["apps", "releases", "listing"]
```

`sha256` — ровно 64 шестнадцатеричных символа; сам токен вместо хеша — ошибка запуска. Имена и хеши не должны повторяться; неизвестные поля, неизвестные наборы и уровни — тоже ошибка запуска. Чтобы отозвать токен, удалите его запись и перезапустите сервер. Файл токенов хранит только хеши, но лучше держать его закрытым: по нему видно, какие клиенты и с каким уровнем есть у сервера.

### Вход пользователя на сервере

Профиль со [входом пользователя](api-client.md#вход-пользователя-oauth-клиент) тоже можно обслуживать по HTTP. Оператор входит на машине сервера (`auth login --oauth --profile <профиль>`, с `--no-browser`, если там нет браузера) и запускает `serve --http --profile <профиль>`. Сервер берёт OAuth-клиент и refresh token из системного хранилища этой машины, а новый refresh token сохраняет туда же. Запросы всех клиентов идут от имени этого пользователя в команде профиля. Агенты получают в инструкциях и ошибках подсказки для оператора, а не команды CLI. `--region`, не совпадающий с сайтом команды, — ошибка запуска. С `--secret-file` вход пользователя не используется: файл секрета всегда задаёт API-клиент. Операции Comments API такой сервер не вызывает. Remote Configuration и App Linking по-прежнему работают через API-клиент проекта из профиля.

## Файл секрета

`--secret-file <путь>` читает учётные данные API-клиента из файла вместо системного хранилища. Это единственный случай, когда сервер берёт их не из хранилища; флаг есть только у `serve --http` и только в Linux и macOS. Файл должен быть обычным файлом (символическая ссылка на него, как у секретов Kubernetes, допускается) с правами только для владельца — `0600` или `0400`; иначе сервер не запускается. Содержимое и путь в ответы MCP не попадают.

Два формата:

- Только секрет API-клиента одной строкой (перевод строки в конце допускается). Идентификатор клиента — не секрет, его передают флагом `--client-id <ID>`:

  ```bash
  appgallery-connect-mcp serve --http --access-tokens tokens.toml \
    --secret-file /run/secrets/agc-client-secret --client-id <Client ID> --region de
  ```

- JSON с обоими значениями — в том же виде, что у `key exec --format json` ([key exec](cli.md#key-exec)); `--client-id` тогда не передаётся:

  ```json
  {"client_id": "<Client ID>", "client_secret": "<секрет>"}
  ```

`--region` (`cn`, `de`, `sg`, `ru`) выбирает сайт AppGallery Connect ([Регион и хост](api-client.md#регион-и-хост)). Без него — регион профиля `--profile`, если профиль сохранён в `profiles.toml`. С `--secret-file` без сохранённого профиля (например, в контейнере) `--region` обязателен: регион по умолчанию не подставляется, иначе сервер молча смотрел бы не на тот сайт, и это выяснилось бы только на первом вызове API. Флаг работает и без `--secret-file`: тогда он заменяет регион профиля.

## Запуск на машине

```bash
appgallery-connect-mcp auth login --profile shared
appgallery-connect-mcp serve --http --profile shared --access-tokens ~/agc/tokens.toml
# appgallery-connect-mcp: MCP endpoint http://127.0.0.1:8769/mcp
```

Флаги HTTP-режима:

| Флаг | Что делает |
| --- | --- |
| `--http` | Обслуживать MCP по HTTP вместо stdio. |
| `--listen <IP:порт>` | Адрес, по умолчанию `127.0.0.1:8769`. |
| `--access-tokens <путь>` | Файл токенов доступа (обязателен). |
| `--secret-file <путь>` | Учётные данные API-клиента из файла секрета (`0600` или `0400`) вместо системного хранилища. |
| `--client-id <ID>` | Идентификатор клиента для файла секрета, в котором только секрет. |
| `--region <регион>` | Сайт AppGallery Connect: `cn`, `de`, `sg` или `ru`; по умолчанию регион профиля, без сохранённого профиля обязателен. |
| `--allowed-host <имя>` | Дополнительное допустимое значение `Host` (имя — с любым портом, или `имя:порт`); повторяемый. |
| `--allowed-origin <origin>` | Допустимый `Origin` браузерного клиента, например `http://localhost:6274` (`:*` — любой порт); повторяемый. |
| `--max-request-bytes <байты>` | Лимит тела запроса, по умолчанию 1048576 (1 МиБ); больше — `413`. |

Остальные флаги `serve` (`--allow-write`, `--allow-destructive`, `--toolsets`, `--tools-file`, `--allow-path`, `--timeout`, `--max-response-bytes`, `--log-level`) работают как в [справочнике CLI](cli.md#serve). Приложения и пакеты по умолчанию берутся из профиля в `profiles.toml`, а наборы профиля — нет. Права сервера с учётными данными из хранилища — права профиля, суженные флагами; с `--secret-file` — флаги сервера. Уровень каждого клиента дальше ограничивает файл токенов.

`Host` запроса должен быть loopback-именем, адресом `--listen` или `--allowed-host`, иначе `403` (защита от DNS rebinding). Запросы из браузера с заголовком `Origin` отклоняются, пока `Origin` не разрешён `--allowed-origin`. Сервер завершается по SIGINT и SIGTERM. Логи — в stderr; в них есть имя токена (`name`), но не сам токен.

Вне loopback ставьте сервер за reverse proxy с TLS (nginx, Caddy, Traefik) или в закрытую сеть и добавьте имя прокси через `--allowed-host`: сервер говорит по обычному HTTP, а токены доступа идут в заголовках.

## Docker

В репозитории есть `Dockerfile` (статический бинарник musl в минимальном образе Alpine, пользователь `10001`, `HEALTHCHECK` по `/health`) и пример `compose.yaml`.

```bash
mkdir -p secrets
printf '%s' '<секрет API-клиента>' > secrets/agc-client-secret   # или скопируйте файл секрета
sudo chown 10001 secrets/agc-client-secret   # владелец — пользователь контейнера
chmod 600 secrets/agc-client-secret
# tokens.toml — рядом с compose.yaml, см. «Токены доступа»
AGC_CLIENT_ID=<Client ID> AGC_REGION=de docker compose up --build -d
curl http://127.0.0.1:8769/health
```

- Секрет монтируется секретом Compose `/run/secrets/agc-client-secret` и в образ не попадает (`secrets/` исключён `.dockerignore` и `.gitignore`). Файл секрета Docker Compose монтирует с правами и владельцем файла хоста, поэтому владельцем должен быть uid `10001` (или запускайте контейнер с `user:` владельца файла). Файл с правами для группы или остальных сервер не принимает.
- Идентификатор клиента и регион приходят в `command` из переменных `AGC_CLIENT_ID` и `AGC_REGION`, которые подставляет Compose; без них Compose не запускает сервис. Сам сервер переменные окружения для учётных данных не читает.
- Файл токенов монтируется только на чтение в `/etc/appgallery-connect-mcp/tokens.toml`.
- Порт публикуется только на loopback хоста (`127.0.0.1:8769`). `--allowed-host appgallery-connect-mcp` в примере разрешает обращения других контейнеров той же сети по имени сервиса.
- Уровень доступа сервера и наборы по умолчанию добавляйте в `command` (`--allow-write`, `--toolsets apps,releases`). Контейнер работает с `read_only`, без capabilities и с `no-new-privileges`. Для инструментов с файлами смонтируйте каталог с правами на запись для uid `10001` и передайте его в `--allow-path`.

Без Compose: точка входа образа — сам бинарник, команда `serve` с регионом передаётся после имени образа (без аргументов образ печатает справку `serve`). Здесь файл секрета в формате JSON, поэтому без `--client-id`:

```bash
docker build -t appgallery-connect-mcp .
docker run --rm -p 127.0.0.1:8769:8769 \
  -v "$PWD/tokens.toml:/etc/appgallery-connect-mcp/tokens.toml:ro" \
  -v "$PWD/secrets/agc-client.json:/run/secrets/agc-client-secret:ro" \
  appgallery-connect-mcp \
  serve --http --listen 0.0.0.0:8769 --region de \
    --access-tokens /etc/appgallery-connect-mcp/tokens.toml \
    --secret-file /run/secrets/agc-client-secret
```

## Подключение клиента

Клиенту нужны адрес `/mcp` и токен доступа в заголовке `Authorization`. Claude Code:

```bash
claude mcp add --transport http --scope user agc http://127.0.0.1:8769/mcp \
  --header "Authorization: Bearer $TOKEN"
```

Токен сохраняется в конфигурации Claude Code (для `--scope project` — в `.mcp.json` проекта, не коммитьте его).

Codex (`~/.codex/config.toml`), токен — из переменной окружения, в которой запускается Codex (сам `appgallery-connect-mcp` её не читает):

```toml
[mcp_servers.agc]
url = "http://127.0.0.1:8769/mcp"
bearer_token_env_var = "AGC_MCP_TOKEN"
```

Клиенты с форматом `mcpServers`:

```json
{
  "mcpServers": {
    "agc": {
      "type": "http",
      "url": "http://127.0.0.1:8769/mcp",
      "headers": { "Authorization": "Bearer <токен доступа>" }
    }
  }
}
```

`connect` и `key exec` к HTTP-режиму не относятся: они работают с локальным бинарником и системным хранилищем машины агента.

## Проверка

```bash
curl http://127.0.0.1:8769/health
curl -s http://127.0.0.1:8769/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -H "Authorization: Bearer $TOKEN" \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

| Ответ | Причина |
| --- | --- |
| `401` с `WWW-Authenticate: Bearer` | Нет `Authorization: Bearer …`, токен короче 32 символов или его хеша нет в файле токенов. |
| `403` | `Host` не разрешён (`--allowed-host`) или браузерный `Origin` не разрешён (`--allowed-origin`). |
| `413` | Тело больше `--max-request-bytes`. |
| Инструмента нет в `tools/list`, вызов — `isError` с подсказкой | Уровень токена ниже нужного или набор не входит в наборы токена: попросите у оператора сервера токен с нужным уровнем. Инструменты с файлами без `--allow-path` не регистрируются. |
